# Mem-Gallery 사전 확인

공식 코드: https://github.com/YuanchenBei/Mem-Gallery/tree/a93959e1e978a6a7d77798ae92c2ffe41c538c62

공식 데이터: https://huggingface.co/datasets/Ethan-Bei/Mem-Gallery/tree/af912daba984e896e253016b7c7e334ef92c2a6f

- 실제 데이터는 20개 시나리오 JSON이다. VS 306개, VR 174개를 확인했다.
- 고정 시드로 개발 시나리오 두 개를 먼저 분리했다. 개발 10개(VS 5, VR 5), 최종 50개(VS 25, VR 25)를 선택했다. 시나리오·질문 이미지 유무로 비례 층화했고 답변이나 모델 점수는 선정에 사용하지 않았다.
- 최종 50개 중 질문 이미지가 있는 질문은 13개, 개발 10개 중 4개다. 질문 이미지는 모든 조건에 동일하게 제공하며 검색 근거 이미지 전달 수에 포함하지 않는다. 전체 이미지 예산 8개에는 포함한다.
- 선택된 19개 시나리오의 전체 대화 3,759턴, 229세션, 대화 이미지 973개를 검색 대상으로 변환했다. 질문 이미지를 포함해 990개 파일을 로컬에 수집하고 검증했다.
- 공식 run_bench.py는 모든 대화를 저장한 다음 QA를 수행한다. QA의 session_id는 근거 세션 정보이며 질문 시점 필터가 아니다. 별도 질문 timestamp가 없어 공식 처리와 동일하게 해당 시나리오 전체 대화를 사용한다. 다른 시나리오는 검색 및 읽기에서 차단한다.
- 원본의 날짜, 세션, round, image_id, image_caption 및 이미지 파일 참조를 보존한다. 여러 이미지가 있는 턴은 모두 유지한다. 공식 기본 변환기는 첫 이미지만 취하지만 여기서는 데이터의 전체 연결을 보존하며 모든 비교 조건에 같은 처리를 적용한다.
- VS의 답은 원본 image_id이며 공식 지침대로 오름차순 쉼표 구분이다. VR은 일반 텍스트 답이다.
- 공식 평가 모듈은 정규화 EM, stemming 기반 token F1, BLEU-1/2/4를 실제 계산한다. 선택적 LLM judge는 0/0.25/0.5/0.75/1 루브릭을 쓴다. BERTScore 함수는 정의돼 있지만 기본 집계 경로에서는 호출되지 않는다. 소스는 수정 없이 import하며 revision을 검사한다. 이미지 ID 구별 및 stemmed F1의 실제 동작을 검증했다.
- clue는 원본 대화 round ID의 목록이며 VS/VR 모든 후보에서 참조가 유효했다. VS의 명시적 정답 이미지 ID와 VR의 근거 턴에 연결된 이미지 집합은 의미가 다르므로 별도로 표시한다.
- 최종 모델 평가는 아직 수행하지 않았다. 공식 judge 및 oracle Reader 진단, 대화 단위 bootstrap은 남은 작업이다.
