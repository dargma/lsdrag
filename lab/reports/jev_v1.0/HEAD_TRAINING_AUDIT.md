# Decision head 학습·가중치·행동 검증

**저장된 head는 수치적으로 정상이고 학습 197턴을 모두 분류한다. 그러나 과적합·일반화 실패·우연한 최종 EM 개선을 배제할 근거는 아직 부족하다.** 최종 평가의 유일한 EM 0→1 문항은 기존 답도 의미상 맞았던 [형식 개선 사례](qualitative/kerry-condon/README.md)다. 따라서 “새로운 추론 능력을 학습했다”는 결론은 내리지 않는다.

이 문서는 **기존 체크포인트·캐시된 학습 특징·완료된 20문항 실행 기록을 CPU에서만 분석**했다. 새 GPU 작업·문제 재풀이·head 재학습·threshold 조정은 하지 않았다. 독립 development feature 평가도 새로 실행하지 않았다. [검사 수치 전체](head_audit.json) · [CPU 검사 코드](../../../scripts/audit_trained_jev_head.py).

## 1. 무엇을 학습했나

| 구성 | 실제 구현 |
|---|---|
| Reader VLM | `google/gemma-4-E4B-it`, revision `ee0ef6023621cff504d758262d4e04895a5af4a2` |
| Backbone | 모든 파라미터 동결, vision·PLE 경로 유지 |
| head 입력 | 전체 multimodal prefill 이후 마지막 정규화 hidden 2,560차원 |
| head | `Linear(2560, 4)`, weight 4×2560 + bias 4, **10,244개 파라미터** |
| 클래스 순서 | keyword_search / semantic_search / read_chunk / FINAL |
| 라벨 의미 | 성공한 기존 A-RAG가 그 상태에서 고른 행동. 최적 행동이나 정답 여부 라벨이 아님 |
| 실행 방식 | head로 행동 선택, 인자와 최종 답변은 같은 Gemma가 생성 |
| 변경하지 않은 것 | 질문·기본 prompt·tool schemas·기존 M3 corpus/index·이미지 입력 정책·A-RAG iteration 8 |
| 외부 API·모델 | OpenAI/Jev 등의 외부 teacher/decision API 미사용 |

$$
\mathbf{z}=W\mathbf{h}+\mathbf{b},\qquad
p(a\mid s)=\frac{\exp z_a}{\sum_{j=1}^{4}\exp z_j}
$$

$$
\mathcal{L}_{\mathrm{CE}}
=-\frac{1}{N}\sum_{i=1}^{N}\log p(a_i^{\mathrm{teacher}}\mid s_i)
$$

이 softmax는 **teacher 행동의 상대 점수**다. `p(FINAL)=0.99`를 “답변 정답 확률 99%”로 사용하지 않는다.

## 2. 데이터는 얼마나 모았고 실제로 몇 개를 학습했나

새 teacher 풀이는 M3 학습용 82 + QC 통과 MMQA train 37 + MultiHop-RAG 300 = **419문항**을 각 한 번 수행했다. 기존 M3 train60의 세 조건 180궤적은 재풀이 없이 감사·재사용했다. 합계 **599궤적**에서 공식 정규화 EM=1인 성공 궤적만 선택했다. 같은 문항의 여러 조건은 서로 다른 질문으로 중복 계산하지 않았다.

최종 학습 자료는 **서로 다른 45문항·46개 성공 궤적·197턴**이다.

| 자료 | 성공 질문 수 | 사용 궤적 수 | 사용 턴 | keyword | semantic | read_chunk | FINAL |
|---|---:|---:|---:|---:|---:|---:|---:|
| 기존 M3 train60의 성공 궤적 | 4 | 5 | 15 | 5 | 5 | 0 | 5 |
| 새 M3 train82 | 6 | 6 | 18 | 6 | 5 | 1 | 6 |
| MMQA train37 | 1 | 1 | 4 | 1 | 1 | 1 | 1 |
| MultiHop-RAG 300 | 34 | 34 | 160 | 24 | 47 | 55 | 34 |
| **합계** | **45** | **46** | **197** | **36** | **58** | **57** | **46** |

행동 클래스의 턴 비율은 **18.3% / 29.4% / 28.9% / 23.4%**다. 하나의 클래스만 압도하는 학습 자료는 아니다. 클래스가 관측된 서로 다른 성공 문항 수도 keyword 34·semantic 43·read_chunk 36·FINAL 45로 미리 정한 최소 10문항 기준을 통과했다.

다만 **자료의 도메인은 고르게 분포하지 않았다.** 전체 턴의 **81.2%(160/197)**가 이미지 없는 MultiHop-RAG다. 특히 read_chunk 라벨의 **96.5%(55/57)**가 그 자료에서 왔고, M3·MMQA에서는 합계 2턴뿐이다. “텍스트 보완 자료로 학습한 head의 M3 전이 PoC”이며 충분한 멀티모달 행동 학습으로 표현하면 안 된다. 실제 reader_calls의 이미지 수용 기록을 학습 상태까지 누적해 확인하면 **이미지를 입력받은 학습 상태는12/197턴(6.1%)**, 텍스트만 받은 상태는185턴이었다. 이미지 상태가 있는 서로 다른 학습 문항은10개다. 멀티모달 상태에서의 행동을 충분히 학습했는지 특히 불확실하다.

## 3. 분리·라벨 생성·학습 과정

1. **분할 선고정:** 기존 M3 100문항을 qid 기준 train60/development20/test20으로 나눴다. 새 M3 pool에서는 학습82/최종평가20을 결과와 무관하게 고정했다. 새 평가20은 이미지 근거10·비이미지 근거10이다.
2. **보완 순서 선고정:** MMQA는 기존 문서 URL과 이미지 파일/hash QC를 통과한 37문항이다. MultiHop-RAG는 최대1,000개를 고정 순서로 선정하고 전체609개 기사를 검색했다. 정답 evidence_list를 직접 입력하지 않았다.
3. **원래 A-RAG teacher 실행:** 100문항 block마다 성공 라벨의 개수만 확인했다. MultiHop-RAG 300문항 시점에 최소45문항·행동별10문항 조건을 충족하여 수집을 중단했다. wrong-answer 재시도·best-of는 없다.
4. **성공 궤적 선택:** 정답은 실행 후 EM 채점에만 사용했다. 입력은 질문·과거 출력·실제 tool 결과·실제 전달 이미지로 복원했다. 현재/미래 assistant target은 prefill 입력에 넣지 않았다. 강제 최종 호출은 학습 가능한 행동 선택 상태에서 제외했다.
5. **특징 추출:** 동결된 전체 Gemma에서 각 학습 상태를 prefill하고 마지막 hidden만 저장했다. 42층 전체 hidden을 보관하거나 vision/PLE를 우회하지 않았다.
6. **한 번의 고정 head 학습:** seed 20261014, full-batch AdamW, lr 0.001, weight decay 0.01, plain CE, 100 epochs. 197턴 전체를 한 batch로 사용하므로 optimizer update는 **100회**다. LoRA·RL·backbone fine-tuning·class-weighting·resampling·early stopping·설정 sweep을 사용하지 않았다.
7. **고정 체크포인트 평가:** 새 M3 20문항에서 B-HF/D-head를 교차 순서로 각 한 번 실행했다. 두 조건은 같은 HF backend를 사용했다. teacher 수집은 vLLM이므로 수집 시간은 최종 속도 비교에 사용하지 않았다.

[학습 metadata](head_training.json)와 실제 사용 체크포인트 hash를 최종 평가 manifest와 대조해 **동일한 head임을 확인**했다. 학습 문항과 새 test20·기존 development/test 사이 qid 중복은 없다. 이는 **질문 ID 단위 분리**이며 문서/주제 공유나 의미적으로 비슷한 질문까지 배제한 독립 문서 일반화 검증은 아니다.

**학습 기록의 한계:** epoch별 loss curve·초기 랜덤 head 체크포인트는 저장하지 않았다. 현재 기록에서 확인할 수 있는 것은 학습 설정·사용 데이터·최종 loss·최종 가중치다. 나중에 재실행한 loss를 원래 학습 곡선인 것처럼 제시하지 않는다.

## 4. 학습 자체가 수치적으로 망가졌나

원 학습 로그의 마지막 CE는 **0.0338895**다. 이 값은 마지막 optimizer update 직전에 기록됐다. 저장된 최종 head와 캐시한 특징으로 CPU에서 다시 계산한 CE는 **0.0334382**다. 한 번의 마지막 update 차이에 해당하며 같은 시점의 loss라고 섞어 비교하지 않는다.

학습 상태 197턴의 teacher 행동 일치율은 **100%(197/197)**다. 가장 많은 클래스만 예측하는 기준선은 **29.4%(58/197)**다.

행은 학습 라벨, 열은 예측이다.

| 라벨 / 예측 | keyword | semantic | read_chunk | FINAL |
|---|---:|---:|---:|---:|
| keyword | 36 | 0 | 0 | 0 |
| semantic | 0 | 58 | 0 | 0 |
| read_chunk | 0 | 0 | 57 | 0 |
| FINAL | 0 | 0 | 0 | 46 |

따라서 **학습 라벨을 전혀 배우지 못했거나 모든 입력에 하나의 클래스를 출력하는 상태는 아니다.** 그러나 10,244개 파라미터에 45개 질문·197턴은 작다. 학습 100%는 암기·과적합과도 양립하므로 일반화 성능의 증거로 제시하지 않는다. head의 효과가 우연이 아님을 확인한 결과도 아니다.

## 5. 가중치가 고르게 분포해야 하나

**균등한 가중치 분포가 학습 성공 기준은 아니다.** 행동마다 필요한 hidden 방향이 달라 weight 값·norm이 달라지는 것은 자연스럽다. 모든 행이 같아지거나, 값이 비정상적으로 발산하거나, 특정 한 클래스만 출력하는지 확인하는 것이 더 직접적이다.

| 저장된 weight 검사 | 관측 |
|---|---|
| NaN·Inf | 없음, weight/bias 모두 finite |
| weight 최소 / 최대 | -0.05493 / 0.06703 |
| 전체 평균 / 표준편차 | 0.00007245 / 0.013743 |
| 정확히 0인 weight 비율 | 0% |
| weight matrix rank | 4 / 최대4 |
| 클래스 간 상대 weight rank | 3 / 4클래스에서 가능한 최대3 |

| 행 | L2 norm | bias |
|---|---:|---:|
| keyword_search | 0.7133 | -0.01344 |
| semantic_search | 0.6524 | -0.01171 |
| read_chunk | 0.7071 | 0.01328 |
| FINAL | 0.7068 | -0.00252 |

행 간 cosine은 약 **-0.142∼-0.039**로, 서로 같은 벡터로 붕괴한 상태는 아니다. 원 weight의 singular values는 **0.7451 / 0.7229 / 0.7139 / 0.5888**이다. 모든 클래스의 weight에 같은 벡터를 더하면 softmax는 같기 때문에 공통 방향을 뺀 상대 행렬은 최대 rank3이며, 이번에도 rank3이다. 이를 rank 부족이라고 해석하지 않는다.

이 검사들은 **수치 정상성·동일 행 붕괴 여부**를 확인한다. 초기 체크포인트가 없어서 실제 weight 변화량·초기값 대비 이동은 직접 확인하지 않았고, 이 수치만으로 최적화 수렴·의미적 정책 학습·일반화를 입증하지 않는다.

## 6. 학습 밖 실제 평가에서는 어떤 행동을 골랐나

아래는 재실행이 아니라 완료된 20문항의 기록을 세었다. 궤적이 서로 달라 행동 비율을 같은 상태의 분류 정확도로 해석하면 안 된다.

| 행동 | 기존 B-HF | D-head |
|---|---:|---:|
| keyword_search | 14 | 20 |
| semantic_search | 13 | 11 |
| read_chunk | 5 | 3 |
| FINAL | 20 | 20 |
| **합계 Reader 호출** | **52** | **54** |

네 행동이 모두 나타났고 첫 호출에서 FINAL을 택한 문항은 0개다. 그러나 **D-head는 20문항 모두 첫 행동이 keyword_search**였다. 초기 검색 선택의 편향은 남아 있으며, 전체에서 네 클래스가 한 번씩 나왔다는 사실만으로 문맥에 따라 충분히 구분한다고 보증할 수 없다.

FINAL 확률이0.9 이상인 호출은18/20개였고, 그중 **16개는 최종 답변 EM=0**이었다. 행동 확률을 정답 확신도로 사용하면 안 된다는 실제 예다. 이는 올바른 행동 확률 calibration 평가 자체는 아니며, EM 탈락에는 형식 문제도 포함될 수 있다.

또한 전체 20문항의 Reader 호출은 **2.6 → 2.7회/문항으로 조금 늘었다.** 평균 속도 개선을 “호출 수 감소”만으로 설명하면 안 된다. 전체 completion accounting은263.95→184.90토큰/문항, decode는6.181→3.920초/문항으로 줄었다. [한 사례](qualitative/kerry-condon/README.md)에서는3→2회로 줄었지만 전체 경향과 구분한다.

## 7. 정확히 같은 입력 상태에서 기존 방식과 얼마나 일치했나

두 조건의 기존 실행에서 질문·전체 이력·실제 이미지 바이트가 같은 상태만 hash로 연결했다. 새로운 모델 호출은 없다. 최초 상태를 포함해 **20문항·39개 공통 상태**가 확인됐고, 행동 일치율은 **28/39 = 71.8%**였다.

행은 같은 입력에서 기존 Gemma가 택한 행동, 열은 head의 행동이다.

| 기존 행동 / head 행동 | keyword | semantic | read_chunk | FINAL |
|---|---:|---:|---:|---:|
| keyword | 14 | 0 | 0 | 0 |
| semantic | 6 | 5 | 0 | 1 |
| read_chunk | 0 | 0 | 2 | 3 |
| FINAL | 0 | 0 | 1 | 7 |

기존이 read_chunk를 선택한 공통5상태 중3상태에서 head는 FINAL을 택했다. 이것은 **기존 정책보다 이른 종료를 선택하는 경향**의 관측이며, 그것이 항상 오답이라는 뜻은 아니다. 상세 사례에서는 snippet으로 답할 수 있었지만, 다른 문제에서 필요한 근거 탐색을 생략하는 위험은 남아 있다.

**이 71.8%는 독립 development 정확도가 아니다.** 이미 본 final-test 실행에서 두 경로가 공유한 prefix만 비교한 사후 진단으로, 이후 경로가 갈라진 상태는 제외되어 선택 편향이 있다. 기존 Gemma 행동도 최적 정책 정답이 아니며, 단순 행동 불일치를 성능 실패로 세지 않는다. 학습197턴의100%와 직접 같은 분포의 train/validation gap이라고 계산하면 안 된다.

## 8. 우연히 좋아진 것 아닌가: 현재 결론

현재 확인한 범위는 **수치적으로 정상인 head가 학습 라벨을 맞히고, 실제 평가에서 툴/FINAL을 선택해 실행 경로를 바꾼다**는 것이다. 다음 이유로 “학습이 일반화해 답변 정확도를 높였다”는 결론은 보류한다.

- 학습 자료는45개 질문으로 작고 텍스트 보완 도메인에 치우쳤다. 학습100%여도 과적합은 배제하지 못한다.
- 평가20문항의 EM은1→2개다. 유일한 차이는 기존도 의미상 맞았던 긴 `No, ...`를 `No`로 정리한 것이다.
- 비교에는 head 외에 **툴 prefix·FINAL JSON prefix·출력 길이·탐색 경로 변화**가 함께 포함됐다. head 없이 FINAL 출력 형식만 맞춘 대조군은 없다.
- 학습 seed 반복, 독립 development 행동 평가, 더 큰 답변 평가를 수행하지 않았다. 따라서 우연성·학습 안정성·정확도 개선의 일반성을 검증하지 못했다.

**보고할 수 있는 결과:** 제한된 PoC에서 전체 실행 시간이 줄었고, 수치 붕괴 없는 head가 행동 선택을 수행했다. **보고하면 안 되는 결과:** 새로운 추론 능력을 학습했다, 정확도 유지/향상이 확정됐다, 높은 FINAL 확률로 안전한 종료를 보장한다.

사용자 요청에 따라 이번에는 문서·CPU 기록 분석까지 마치고 GPU 작업을 시작하지 않았다. 위 미확인 항목은 후속 검증 필요 사항으로 남기며 추가 실험을 실행한 것처럼 쓰지 않는다.
