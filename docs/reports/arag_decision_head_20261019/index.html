BACKGROUND

1. 배경과 연구 질문

Jev 같은 decision 모델을 보면서 출발한 생각은 단순했다. “판단할 때마다 문장을 생성하지 않고, 필요한 선택만 바로 내리면 빠르지 않을까?” 이를 검색·읽기·종료를 매 단계 결정하는 Agentic RAG에 적용했다. 질문은 reader LLM에 작은 decision head를 붙여, Native A-RAG 방식의 정확도를 유지하면서 응답 시간을 줄이고 나아가 더 나은 행동을 고를 수 있는가이다.

A-RAG는 keyword search, semantic search, chunk read를 모델에 노출하는 계층적 검색 인터페이스를 제안한다. 이번 연구는 이 세 도구를 사용하는 텍스트 전용 로컬 실험이다. 아래의 “Native”는 동일 Qwen reader가 도구 이름·인자 또는 최종 답변을 직접 생성하는 이 저장소의 비교 구현을 뜻한다. 원 논문의 전체 벤치마크 재현이나 공식 A-RAG 점수와의 직접 비교는 아니다. Jev 모델/API를 사용하거나 재현한 실험도 아니다. A-RAG 원 논문 · Jev 제공사 TypeSafe

세 가지 가설을 분리한다.
  1. 행동 선택을 짧은 분류 연산으로 바꿔 순차 생성을 줄일 수 있는가?
  2. 그렇게 바꾼 정책이 실제 QA 정확도를 유지하거나 높이는가?
  3. read 인자 선택 또는 trajectory 최적화로 생성량·호출 수를 더 줄일 수 있는가?
이번 결과는 첫 가설의 구현과 관측 효율 가능성을 지지한다. 두 번째의 통계적 입증은 부족하며, 세 번째 중 read 선택은 품질 채택 기준에 실패했다.

2.2 질문 분리와 teacher 라벨

MuSiQue train에서 수집한 teacher 32문항을 기존 고정 split에 따라 train 24문항 / validation 8문항으로 나눴다. teacher는 같은 reader의 Native 경로다. 각 상태에서 teacher 출력을 보기 전 reader의 마지막 token hidden을 추출하고, teacher가 고른 행동을 정답 라벨로 저장했다. 이후의 최종 답변 gold는 QA 평가에 사용했다. 이 32문항은 개발 과정에 이미 노출된 자료이며 validation8을 완전히 독립적인 최종 test로 부르지 않는다.

초안과 실제 실행의 차이: “정답인 trajectory만 학습”한 것이 아니다. 수집된 natural-state 기록을 그대로 학습에 사용했다. train 24문항 중 teacher EM 정답은 5문항이며, 82개 상태 중 65개가 teacher의 최종 EM이 0인 문항에서 나왔다. 부분점수 답변도 EM=0에 포함된다. 이 수치는 복원한 teacher JSON에서 재집계했다. 현재 head는 정답 행동의 최적화가 아니라 teacher 행동 모방(behavior cloning)을 학습한다.

학습 상태의 행동 수는 keyword 24 / semantic 18 / read 16 / FINAL 24다. 서로 다른 질문 수 기준으로는 각각 23 / 18 / 16 / 24이며, 모든 행동에 최소 5개 질문이 있는 coverage gate를 통과했다. read 재사용 라벨은 11개 질문, GENERATE는 5개 질문이다. read slot 라벨 분포는 GENERATE=5, slot1=2, slot2=6, slot3=3, slot4=0으로, 후보 4의 학습 양성은 없었다.

validation에서 인자 선택을 평가해 always-generate를 주조건으로 동결한 뒤 fresh dev 20문항으로 먼저 비교했다. 그 20문항에 대한 read 선택 ON/OFF 후속 분석은 이미 노출된 문항의 탐색 평가다. 마지막 확인은 기존 질문 및 하위질문 family를 제외한 새 dev 100문항으로 수행했다. 원래 answerable 2-hop dev 1,252개 중 1,099개가 기존 노출 제외 조건을 만족했고, 결과를 보지 않는 hash 순서와 새 집합 내부 family 중복 배제로 100개를 고정했다. 이는 dev 전체의 무작위 표본과 같지 않으며 사전학습 데이터 노출까지 배제한 것은 아니다. 새 100문항은 학습·튜닝에 사용하지 않았다.

head는 공개 관측으로 가능한 행동만 남기는 legal mask 후 argmax를 고른다. 관측된 ID가 없으면 read를 막는다. read-slot 라벨은 현재 후보와 teacher 인자가 정확히 같을 때 해당 slot, 없으면 GENERATE다. gold support를 보고 가장 좋은 문단을 가르치는 학습은 아니다. 검색 인자는 v3에서 항상 생성한다. 최종 100문항 주조건에서는 read 인자 역시 항상 생성하며 slot 예측은 인자 실행에 사용하지 않는다.

고정 teacher validation 29상태에서 action macro-F1은 0.81399였고 premature FINAL은 0개였다. 이는 teacher 상태에서의 행동 모방 지표이며 head가 스스로 방문한 상태에서 문제를 잘 푼다는 뜻은 아니다. 실제 validation8 자율 QA의 always-generate F1은 21.875%, EM은 12.5%로 별도 보고한다.

번호 선택에서 실제 함수 호출까지

도구 선택은 텍스트 생성 대신 head 출력의 argmax 인덱스로 결정한다. 번호 매핑은 0 → keyword_search, 1 → semantic_search, 2 → read_chunk, 3 → FINAL이다. 숫자 “1”을 LLM이 한 토큰으로 생성하는 방식도 아니다. 네 점수 중 가장 큰 값을 갖는 인덱스를 코드가 읽는다. 합법 행동 mask를 적용하므로 사용할 수 없는 도구는 선택되지 않는다.

위 query는 구조 설명용 예시이며 raw 로그를 인용한 것이 아니다. 실제 문항의 생성 문자열은 4.3절과 단계별 원본 기록에 있다. FINAL(번호 3)은 외부 검색 함수를 호출하지 않고 답변 JSON 생성으로 분기한다.

어디서 빨라지는가? Native가 “어떤 도구를 호출할지”를 도구 이름과 호출 구문으로 순차 생성하던 부분을, head의 번호 선택과 runtime의 고정 구문 공급으로 대체한다. 다만 구문 토큰을 모델에서 전혀 처리하지 않는 것은 아니다. 같은 KV에 고정 prefix를 한 번에 반영하고 인자 생성으로 이어간다. 그러므로 핵심은 도구 선택·고정 구문에 대한 순차 decoding을 줄이는 것이다. 인자와 최종 답변 생성은 남는다.

번호 1을 선택했다고 즉시 검색 함수가 실행되는 것은 아니다. 최종100 조건에서는 인자를 생성한 뒤 호출한다. 별도 read-slot 실험에서는 이미 관측한 chunk_ids 후보를 선택했을 때만 인자 생성 없이 바로 실행했다. 또한 이번 26.8% 시간 감소는 head·prefix batch·cache 연결·schema 제약이 함께 바뀐 결과다. “도구 이름 생성 하나를 없애서 26.8% 빨라졌다”는 단독 기여 측정은 아니다.

2.4 인자 생성과 KV cache: 무엇을 줄였는가

도구를 고르는 순간에도 전체 문맥의 prefill은 필요하다. 이후 <tool_call> … "name": "선택한 도구", "arguments": {" 같은 고정 구문은 runtime이 공급하고, 하나의 batch forward로 cache에 반영한다. 그 뒤 필요한 keyword/query/chunk_ids와 FINAL 답변을 같은 frozen LLM이 생성한다. 선택 후 인자 생성 때문에 같은 문맥을 두 번째 full-prefill하지 않는다. FINAL은 저장된 마지막 hidden의 LM logits에서 시작하며 도구 prefix를 강제하지 않는다.

이 KV 재사용은 한 turn 안의 decision→argument/final 연결이다. 새 도구 결과가 붙은 다음 turn에는 전체 대화를 다시 prefill한다. 문서 자체를 KV에 압축 저장하거나 모든 turn의 prefill을 없앤 실험은 아니다. read 후보 선택은 “기존 ID 인자를 복사할지”의 문제로 KV cache 재사용과 별개다.

초기 compact 구문 경로는 24상태 중 7개에서 인자 값이 달라져 채택하지 않았다. native-spaced aligned 경로는 고정 train 24상태의 값이 Native와 24/24 일치하고 추가 full-prefill이 없었다. 2개 상태의 FP32 cache/full 차이는 최대 약 5.48×10⁻⁵, argmax도 일치했다. 이는 제한된 기능 진단이지 모든 상태의 수치 동등성이나 QA 성공 증명은 아니다.

Native는 unconstrained native payload를 생성하고 사후 schema를 검증한다. Head 조건에는 schema를 지키도록 생성 토큰을 제한하는 경로도 있다. 따라서 비교에는 정책 head + 고정 구문 처리 + cache 연결 + 형식 제약이 함께 포함된다. learned head 하나만의 순수 인과 효과로 읽으면 안 된다.

성공 — Prince Prigio: 두 조건 모두 첫 keyword 검색으로 작가가 Andrew Lang이고 책 출판연도가 1889라는 같은 결과를 받았다. Native는 p3를 읽은 뒤 1889를 답했다. 5. 시사점과 후속 연구 제안

5.1 확인한 것과 아직 확인하지 못한 것

작은 head는 Native의 선택·구문 생성을 줄이는 실행 구성요소로 동작했다. 100문항에서 품질 점추정이 비슷한 상태로 26.8% 짧은 episode 시간을 관측한 것은 후속 검증의 근거가 된다. 다만 순차 decoding 대부분은 인자와 답변 생성으로 남고, 도구 수·입력 길이는 늘었다. “판단만 빠르게 하면 agent 전체가 같은 비율로 빨라진다”는 처음 가설은 조건부다.

Native와 head가 서로 다른 정답을 얻는다는 사실은 Native 정확도가 절대 상한이 아님을 보여주는 사례다. 그러나 현재 loss는 Native 행동의 CE 모방이므로 그보다 좋은 trajectory를 체계적으로 학습할 신호가 없다. 마지막 hidden 하나와 작은 linear head가 전체 KV를 참조하며 추가 decode하는 Native와 같은 판단 능력을 갖는다는 가정도 성립하지 않는다.

5.2 우선순위 1 — 최적화된 Native를 기준으로 head의 잔여 가치를 측정

미실행 제안: N-full(현재 Native), N-fast(동일 구문 처리·cache·형식 안정화를 제공한 Native 선택), H-BC(현재 head)를 비교한다. 동일 상태에서 같은 행동·인자·답변을 고정한 비용 검사와 전체 episode 품질 평가를 분리한다. warmup·조건 순서 교대·반복 측정과 GPU 부하 기록을 포함한다. 먼저 학습 없이 얻을 수 있는 시간 이득을 분리해야 head 학습 자체의 가치를 알 수 있다.

5.3 우선순위 2 — trajectory 라벨의 목표를 모방에서 실제 효용으로

미실행 제안: train 안에서 현재 head 정책 πk가 방문하는 상태를 수집한다. 같은 관측 상태에서 합법 대안 행동을 실제로 실행하고, 인자 생성기는 고정한 채 πk로 남은 episode를 완료한다. 각 행동의 최종 F1·EM·근거·오류와 남은 tool calls·decoder/input 비용을 라벨로 저장한다. 이는 Qπk를 추정하는 것이며 전역 최적 행동을 안다는 뜻은 아니다.

같은 branch 데이터에서 단순 best-action CE와 작은 quality/cost 예측 head를 비교하고, 기존 imitation CE 및 간단한 turn/empty-result 규칙을 강한 비교군으로 둔다. 비용만 최소화해 즉시 FINAL로 무너지는 일을 막기 위해 품질을 우선하고 조기 오답 종료를 별도 집계한다. 미래 결과·gold는 학습 target에만 사용하며 inference feature에 넣지 않는다. 새 정책 πk+1는 처음부터 끝까지 실행해 다시 평가하고, 정책이 바뀌면 방문 상태와 suffix 가치도 다시 수집해야 한다.

성공 trajectory만 남기는 방식도 학습 후보이지만, 성공한 경로가 최소 비용이거나 모든 중간 행동이 좋았다는 보장은 없다. 실패 이후의 복구 상태를 잃을 수 있으므로 성공-only BC, 모든 상태 BC, outcome-weighted BC, branch-value 학습을 같은 질문·수집 예산에서 비교하는 편이 해석에 유리하다. 기존 새100은 학습 데이터로 재사용하지 않는다.
