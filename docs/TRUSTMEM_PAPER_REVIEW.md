# TrustMem 논문 정리 — 장기 기억을 갱신하는 과정의 신뢰성 학습

**TrustMem은 LLM 에이전트가 기억을 추가·수정·삭제할 때 생기는 누락·왜곡·환각을 줄이는 학습 방법이다.** 기억 갱신 전후를 검증하고, 같은 상태에서 생성한 더 좋은 갱신을 선호하도록 정책을 학습한다. 임베더나 이미지 검색 모델을 제안하는 논문은 아니다.

2026-10-14 원문 확인. 아래 수치는 논문 저자의 보고이며 이 저장소에서 재현한 결과가 아니다.

## 2. 해결하려는 문제

장기 기억 에이전트는 긴 대화나 문서를 조금씩 읽고 외부 메모리를 갱신한다. 한 번 잘못 저장한 사실은 이후 검색에서 반복해서 불려 나와 여러 답변에 영향을 줄 수 있다. 최종 답이 맞았다는 사실만으로 중간의 기억 갱신이 모두 정확했다고 판단할 수 없다.

| 실패 | 의미 | 논문의 예 |
|---|---|---|
| Omission · 누락 | 나중에 필요한 핵심 정보를 저장하지 않음 | 밴드의 결성은 저장하지만 해체·재결합 연도는 빠뜨림 |
| Corruption · 왜곡 | 근거 있는 사실의 시기·관계·부정 등을 바꿈 | 18세기 문인을 17세기에 배치하거나 ‘남아 있지 않다’를 반대로 저장 |
| Hallucination · 환각 | 입력·기존 기억이 뒷받침하지 않는 사실을 추가 | 식물 설명에 무관한 철도 인물 정보를 끼워 넣음 |

핵심은 **최종 기억의 유용성**과 **각 갱신의 정확성**을 함께 학습하는 것이다. [원문 §1, Figure 1, Table 5](https://arxiv.org/html/2606.25161v1#S1)

## 3. 전체 동작

입력 청크를 시간순으로 처리한다. 현재 청크 `c_t`와 이전 기억 `M_(t−1)`을 받은 정책이 편집 행동 `a_t`를 생성하고, 결정적인 실행기가 이를 적용해 새 기억 `M_t`를 만든다.

```text
현재 청크 + 기존 기억
        ↓
기억 정책이 Write / Revise / Prune 생성
        ↓
실행기가 편집 적용 → 새 기억
        ↓
갱신 전후·근거·편집 행동을 Verifier가 평가
        ↓
학습 보상 + 같은 상태의 후보 간 선호 순위
```

| 행동 | 기능 |
|---|---|
| Write | 아직 저장되지 않은 유용한 정보 추가 |
| Revise | 기존 항목을 정정·보완·병합 |
| Prune | 근거상 무효·중복·불필요해진 항목 제거 |
| 행동 없음 | 이미 올바르게 저장된 정보 등 갱신할 필요가 없는 경우 |

한 갱신의 평가 단위는 `z_t = (c_t, M_(t−1), a_t, M_t)`다. 모든 청크를 처리한 뒤 최종 기억에서 **고정 retriever**가 근거를 검색하고 **answer model**이 답한다. 학습 대상은 이 기억을 만드는 정책이다. [원문 §3.1](https://arxiv.org/html/2606.25161v1#S3.SS1)

## 4. Memory Transition Verifier

Verifier는 동결된 LLM이다. 전체 기억 은행을 모두 읽히기보다 현재 청크, 편집 행동, 관련되거나 변경된 기억의 전후 상태를 제공한다.

| 기준 | 검증 질문 | 주로 연결되는 오류 |
|---|---|---|
| Coverage | 새 입력의 저장할 가치가 있는 핵심 정보가 반영됐는가? | 누락 |
| Preservation | 유효한 기존 기억을 근거 없이 지우거나 바꾸지 않았는가? | 왜곡·부당 삭제 |
| Faithfulness | 새로 쓰거나 수정한 내용이 입력 또는 기존 기억으로 뒷받침되는가? | 환각·왜곡 |

Verifier는 0~1 점수와 진단을 출력한다. 이미 기억에 있는 사실을 다시 쓰지 않는 것, 중요한 사실을 유지하는 압축·병합은 허용한다. **최종 답변 판정기와 기억 전이 검증기는 역할이 다르다.** [원문 §3.2, Figure 5](https://arxiv.org/html/2606.25161v1#S3.SS2)

추론 때 모든 갱신을 임계값으로 차단하는 배포 정책과, Verifier 점수를 이용해 기억 정책을 학습하는 것은 구별해야 한다. 논문의 중심 기여는 후자의 학습 체계다. 구체적인 운영 환경의 승인·롤백 정책까지 성능이 입증됐다고 해석하지 않는다.

## 5. 보상 설계

최종 과제 결과와 각 기억 편집을 함께 평가한다. 실제 실험의 가중치는 다음과 같다.

```text
R = R_task + R_act + 0.1 R_ver + 0.05 R_eff + 0.1 R_type
```

| 보상 | 평가 대상 | 역할 |
|---|---|---|
| R_task | 입력 전체 처리 후의 기억 기반 과제 성능 | 실제 쓸모 있는 기억 유지 |
| R_eff | 최종 기억의 길이 대비 원 입력 길이 | 원문을 무작정 복사하는 메모리 팽창 억제 |
| R_act | 행동 파싱·실행 가능 여부 | 실행 가능한 편집 학습 |
| R_type | 수정 내용의 구체성·비어 있지 않음 | 내용 없는 형식적 갱신 억제 |
| R_ver | 각 전이의 근거 보존·충실성 | 중간 편집의 의미적 오류 억제 |

논문 정의에서 `R_eff = 1 − |최종 기억| / Σ|입력 청크|`다. 최종 과제 보상은 여러 전이에 공통으로 주어지고, 행동·내용·검증 보상은 해당 전이를 평가한다. 작은 Verifier 가중치 하나만으로 구성된 방법이 아니다. [원문 §3.3, §4.1](https://arxiv.org/html/2606.25161v1#S3.SS3)

## 6. Transition-Ranked GRPO

Verifier 점수의 절대값이 완벽하게 보정되어 있지 않아도, **같은 상태에서 어느 갱신이 더 나은지**는 유용한 신호가 될 수 있다는 접근이다.

1. 학습 샘플당 기존 정책에서 **8개 rollout**을 만든다.
2. 청크 단계별 보상에서 그룹 평균과 표준편차로 advantage를 계산해 GRPO로 학습한다.
3. 같은 청크·이전 기억 상태의 후보 중 Verifier 점수가 가장 높은 행동과 가장 낮은 행동을 고른다.
4. 점수 차이가 **0.15 초과**인 경우에 선호 쌍을 만든다.
5. 더 좋은 행동의 길이 정규화 로그확률을 상대적으로 높이는 **DPO 형태의 순위 손실**을 더한다.

```text
L = −J_GRPO + β_KL L_KL + λ_rank L_rank
L_rank = −log sigmoid(β_rank × (Δ_policy − Δ_reference))
```

여기서 `Δ`는 같은 프롬프트에서 선호 행동과 비선호 행동의 길이 정규화 로그확률 차이다. rollout을 만든 이전 정책과, KL·순위 기준인 동결 reference 정책을 구분한다. KL은 advantage 계산에 넣는 보상이 아니라 **actor 측 보조 손실**이다. [원문 §3.4, 식 2–4](https://arxiv.org/html/2606.25161v1#S3.SS4)

재현할 때 중요한 점은 **같은 이전 기억 상태**를 공유하는 후보만 비교하는 것이다. 독립 rollout이 다른 기억 상태로 분기했다면 청크 번호만 같다는 이유로 선호 쌍을 만들면 안 된다. 논문은 같은 상태의 쌍을 전제로 쓰지만, 실제 rollout 분기와 상태 고정을 처리하는 세부 코드는 원문 설명만으로 충분히 확인되지 않는다.

## 7. 실험과 학습 설정

| 항목 | 논문 설정 |
|---|---|
| 기억 정책 초기 모델 | **Qwen3-4B**, thinking mode 비활성화 |
| 학습 자료 | Mem-α 학습 풀 4,139개 중 균형 선정한 **562개** |
| 검증 자료 | Mem-α held-out **463개** |
| 학습 출처 | SQuAD, HotpotQA, PerLTQA, LongMemEval-Train, NLU, TREC-C, PubMed-RCT, BookSum |
| 외부 평가 | MemoryAgentBench, HaluMem-Medium; 두 벤치마크의 예제는 학습에 사용하지 않았다고 보고 |
| 자원·체크포인트 | H100 32장으로 약 2일, step-85 결과 |
| 학습률 / KL 계수 | 1e−6 / 0.001 |
| 최대 prompt / response | 4,096 / 2,048 tokens |
| 순위 손실 | λ_rank=0.05, β_rank=0.1 |
| 선호 쌍 | batch당 최대 256개, GPU당 pair micro-batch 1 |

MemoryAgentBench는 정확 검색(AR), 예시에서 규칙을 습득하는 test-time learning(TTL), 긴 문맥 통합(LRU)을 평가한다. TTL은 이 평가에서의 과제 이름이며, 평가 때 모델 가중치를 추가 학습했다는 뜻으로 읽으면 안 된다. HaluMem-Medium은 20명·30,073 대화 턴·14,948 기억 항목·3,467 QA 쌍으로 추출·갱신·답변을 나눠 평가한다. [원문 §4.1](https://arxiv.org/html/2606.25161v1#S4.SS1)

논문이 명확히 지정한 **GPT-4o-mini, temperature 0**은 §4.5의 전이 오류 평가 judge다. 학습용 동결 Verifier의 구체적인 모델명까지 같은 것으로 단정하지 않는다. RAG-Top2 기준선은 BM25 top-2 + Qwen3-32B이며, 이 저장소의 Gemma Reader·임베더 비교와 다르다.

## 8. 주요 결과

### 8.1. 기억 유용성

| 평가 | 강한 비교 기준 | TrustMem | 차이 |
|---|---:|---:|---:|
| Mem-α 검증 평균 | Mem-α 61.9 | **66.3** | +4.4점 |
| MemoryAgentBench 평균 | Mem-α 59.2 | **65.7** | +6.5점 |
| HaluMem 추출 F1 | Mem0 57.31 | **69.45** | +12.14점 |

앞 두 평균은 서로 다른 과제 점수의 **macro-average**다. 모든 과제에 동일한 정확도 척도를 쓴 결과가 아니며, HaluMem F1과도 직접 합산하지 않는다. [원문 Tables 1–3](https://arxiv.org/html/2606.25161v1#S4.SS2)

평균 개선이 모든 세부 과제의 개선을 뜻하지는 않는다. MemoryAgentBench Multi-Doc은 Mem-α 68.0 → TrustMem 64.0, 검증 PerLTQA는 65.9 → 63.6으로 낮아졌다.

### 8.2. HaluMem의 단계별 결과

| 단계·지표 | TrustMem | 해석에 필요한 비교 |
|---|---:|---|
| 기억 추출 recall | 56.73 | 표의 최고 |
| 기억 추출 weighted recall | 67.45 | 표의 최고 |
| 기억 추출 accuracy | 67.81 | 최고 아님; AtomMem 87.50이지만 recall 0.28 |
| 기억 갱신 correctness | 46.84 | Zep 47.28보다 낮음 |
| 기억 갱신 hallucination | 0.53 | Zep 0.42, Mem0 0.45보다 높음 |
| 기억 갱신 omission | 48.64 | 표의 최저지만 절대 누락률은 여전히 큼 |
| QA correctness | 55.22 | Mem-T 59.43보다 낮음 |
| QA hallucination | 6.07 | AtomMem 5.56보다 높음 |
| QA omission | 12.46 | 표의 최저 |

핵심 강점은 무조건 적게 쓰는 방식보다 **기억을 놓치지 않으면서 올바르게 보존하는 균형**이다. 모든 정확성·환각 지표에서 최고라고 쓰면 잘못이다. [원문 Table 3, Appendix C](https://arxiv.org/html/2606.25161v1#S4.SS3)

### 8.3. 별도의 전이 오류 감사

| 오류 종류 | TrustMem 전이 오류율 | 해당 오류의 최강 기준선 대비 상대 감소 |
|---|---:|---:|
| 누락 | **8.08%** | 40.1% |
| 왜곡 | **0.14%** | 79.1% |
| 환각 | **0.01%** | 50.0% |

이 수치는 **Mem-α 검증 463개에서 나온 청크별 전이**를 GPT-4o-mini가 평가한 결과다. HaluMem의 갱신 누락 48.64%나 QA 환각 6.07%와는 데이터·단위·판정 기준이 다르다.

주요 오류(`major`)만 세며 하나의 전이에 여러 오류가 있으면 각각 집계한다. 따라서 세 오류율은 합이 100%가 되는 분류가 아니다. 40.1·79.1·50.0은 **상대 감소율**이며 %p 차이가 아니다. [원문 §4.5, Figure 2, Appendix D](https://arxiv.org/html/2606.25161v1#S4.SS5)

## 9. Ablation: 무엇이 효과를 냈는가?

| 설정 | 검증 평균 | 전체 모델 대비 차이 |
|---|---:|---:|
| TrustMem 전체 | **66.3** | — |
| 행동 실행 보상 제거 | 54.0 | −12.3 |
| 효율성 보상 제거 | 61.8 | −4.5 |
| 전이 Verifier 보상 제거 | 58.7 | −7.6 |
| PRM-style GRPO | 60.3 | −6.0 |

실행 가능한 행동 학습이 가장 큰 차이를 보였고, Verifier와 순위 기반 학습도 추가 효과를 보였다. PRM-style GRPO 대비 TTL은 57.6→70.1이었다. 단순히 Verifier 점수를 스칼라 보상으로 넣는 것과 **같은 상태의 후보 순위를 학습하는 것**은 같지 않다. [원문 §4.4, Table 4](https://arxiv.org/html/2606.25161v1#S4.SS4)

다만 ablation 행을 근거로 구성 요소 사이의 상호작용을 모두 분리했다고 해석하지 않는다. 특히 R_ver 제거 시 순위 쌍 생성까지 어떻게 바뀌는지는 공개 설명·코드 확인이 더 필요하다.

## 10. 한계와 재현 전에 확인할 점

- **평가 judge 의존:** 전이 오류는 동결 LLM 판정이다. 인간 평가 일치도·반복 판정 변동·신뢰구간을 해당 결과와 함께 제시한 것은 확인되지 않았다. 0.01% 같은 희소 오류는 분모와 불확실성을 특히 확인해야 한다.
- **불완전한 구현 명세:** verifier 모델명, 점수 집계·보정, 동일 상태의 후보 생성, 전체 하이퍼파라미터·seed·체크포인트 재현 정보를 보충해야 한다. 확인한 원문에 TrustMem 공식 코드·가중치 링크는 명시되어 있지 않았다.
- **평가 비용·규모:** 약 32 H100 × 2일의 학습을 보고한다. 적은 학습 샘플 수가 저렴한 학습을 뜻하지 않는다. 실제 서비스의 지연·메모리·Verifier 호출 비용 비교는 별도다.
- **기준선 조건 차이:** 비교 모델 크기와 시스템 구성이 다르고 일부 시스템은 backbone이 고정되지 않았다. 평균 우위를 모든 모델 크기·비용을 통제한 순수 알고리즘 효과로 해석하면 안 된다.
- **과제 범위:** 실험은 주로 텍스트 장기 기억이다. 실제 이미지가 들어가는 멀티모달 기억이나 EmbeddingGemma 2 검색 성능 개선은 입증하지 않았다.
- **운영 정책:** 학습한 메모리 갱신 정책의 성능이 특정 승인·차단·롤백 시스템의 완전성을 증명하는 것은 아니다. 원문 자체가 뒷받침하지 않는 안전 보장은 추가하지 않는다.

위 항목은 원문을 읽고 정리한 **검토 의견**이며, 모두 저자가 명시적으로 한계로 선언한 내용이라는 뜻은 아니다.

## 11. 현재 A-RAG 연구와의 관계 — 적용 제안

현재 저장소는 문서 코퍼스를 검색하고 Reader VLM에 근거를 전달한다. TrustMem은 **장기 기억을 만들어 갱신하는 정책**을 개선한다. 해결하는 단계가 다르므로 현재 임베더 교체 결과에 TrustMem 성능을 그대로 붙일 수 없다.

| 현재 경로 | TrustMem 관점에서 추가할 수 있는 내용 |
|---|---|
| 고정 문서·인덱스 검색 | 현재 경로 유지; 문서 검색 자체를 TrustMem으로 대체할 필요 없음 |
| 대화·문서의 요약 기억을 누적 갱신하는 기능 | Write/Revise/Prune과 변경 전후 snapshot을 명시적으로 기록 |
| 기억 품질 평가 | 최종 QA 외에 누락·왜곡·환각을 전이별 감사 |
| 학습 단계 | 같은 이전 상태에서 여러 후보를 생성하고 근거 기반 선호 쌍 구축 |
| 이미지가 있는 기억 | 원본 figure_id·파일 해시·출처·캡션을 함께 보존하고 텍스트 요약이 픽셀 근거를 왜곡하는지 별도 검증 |

우선 학습 없이 전이 로그와 소규모 오류 감사를 추가해 실제 문제가 있는지 확인하는 것이 현실적인 첫 단계다. 이후 기본 정책의 오류와 검증기 일치도를 측정하고, 충분한 효과가 보일 때 선호 학습을 검토할 수 있다. **이는 이 문서의 적용 제안이며 논문의 멀티모달 실험 결과가 아니다.**
