# Decision policy: 큰 가설을 빠르게 검증하는 실행 계획

## 최신 사용자 방향

“정말 decision model인가? 단순 선택 흉내가 아니라 정확도 향상과 토큰 절약을 위한 정책기인가?”를 중심 질문으로 삼는다. 너무 상세한 ablation 중심 진행은 하지 않는다. 큰 가설 하나, 후보 하나, 실제 QA 평가로 빠르게 방향을 좁히고, 유망한 방향이 확인된 뒤 세부 실험을 확장한다. 기존 골과 native 인터페이스는 유지한다.

## 현재 판단

구조상 현재 MLP는 행동을 선택하는 정책이다. 하지만 유용한 의사결정 정책이라는 실험적 주장은 아직 미입증이다.

- 품질 중심 MLP+GRPO는 F1 34.75까지 갔지만 생성150.91로 비싸다.
- 효율 중심 MLP는 F1 26.74/생성75.45지만 최근 절약은 주로 여전히 오답인 문항의 조기 종료에서 나왔다.
- 학습 상태에서 수정 목표18/21을 반영한 것은 학습 기능 증거일 뿐, 새 문항에서 더 좋은 계산 배분을 한다는 증거가 아니다.

따라서 head 구조를 더 많이 비교하거나 학습 정확도를 높이는 것 자체를 다음 목표로 삼지 않는다. 현재 관측에 따라 **더 찾아야 할 때 찾고, 충분할 때 답하고, 불필요한 실행을 줄이는 정책**을 실제 episode 결과로 판단한다.

## 다음 실험: 결과를 배운 MLP가 계산을 더 잘 배분하는가?

가설: 현재 정책이 방문한 상태에서 행동별 최종 품질과 남은 생성 비용을 학습하면, 현재 MLP보다 유용한 탐색을 선택하고 정답 경로의 낭비를 줄일 수 있다.

방금 완료한 세 번째48문항 자료를 사용한다. 같은 frozen Qwen/native tool 계약에서 얻은 자료이며, 새 구조나 PPO/GRPO를 동시에 바꾸지 않는다. 현재 비용 우선 MLP에서 시작해, 실제 결과가 뒷받침하는 행동을 학습하는 후보 하나를 만든다. 오답에서 오답으로 더 빨리 끝내는 사례는 비용 개선 목표로 쓰지 않는다. 과거 자료는 기존 행동 보존에 사용하며 서로 다른 후속 정책의 outcome을 같은 값으로 섞지 않는다.

현재 MLP와 후보를 같은 개발64문항에서 끝까지 실행한다. 고정 기본 GRPO와 Native의 기존 결과도 함께 제시한다. 주요 판단은 답변 F1, 생성 토큰, 그리고 절약이 정답을 유지한 경로에서 나오는지다. 좋아진 사례와 잃은 사례를 함께 확인하되, 현 단계에서 큰 ablation 행렬이나 별도 분석 실험을 벌이지 않는다.

단순 imitation을 넘어섰다는 초기 근거는 현재 정책과 다른 행동이 실제 정답 회복 또는 정답을 유지한 비용 절감으로 이어지는 것이다. 행동이 달라졌다는 사실이나 학습 loss만으로는 인정하지 않는다. 이 파일럿은 개발 방향 판단이며 독립 입증은 아니다.

## 결과가 말해주는 다음 가설 하나

| 결과 | 다음에 검증할 방향 |
|---|---|
| 정확도와 비용이 함께 좋아짐 | 같은 방향을 유지해 학습 범위·반복성을 넓힌 뒤 독립 평가 준비 |
| 정확도는 좋아지나 비용이 큼 | “탐색 선택보다 계속할지 끝낼지 판단이 병목인가?”를 단일 후속 실험으로 검증 |
| 학습 목표는 반영되지만 실제 QA는 개선되지 않음 | 현재 요약 hidden으로 충분한 상태 판단이 가능한지, 관측 정보를 더 직접 읽는 입력/정책 후보 하나 검증 |
| 실제 행동별 결과에도 유용한 차이가 부족함 | 잘못된 정책 학습을 반복하지 않고, 생성기·검색 결과의 한계를 먼저 확인 |

분기는 자동으로 전부 실행할 목록이 아니다. 완료 결과를 보고 하나씩 선택하며 설정은 실행 전 고정한다. 기존 direct quality/cost 예측기의 실패를 무시하고 같은 실험을 재명명하지 않는다.
