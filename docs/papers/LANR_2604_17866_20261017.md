# LAnR 개별 논문 정리

논문: **Latent Abstraction for Retrieval-Augmented Generation**. 최초 공개2026-04-20, 검토 버전v2(2026-05-07). 2026-10-17에 공개 원문 방법·학습·부록을 확인했다. [논문 페이지](https://arxiv.org/abs/2604.17866v2), [본문](https://arxiv.org/html/2604.17866v2).

## 무엇을 하는가

같은 LLM이 문서를 표현하고, 텍스트 검색어 대신 `[PRED]`의 마지막 hidden에서 검색 벡터를 만들며, 같은 표현으로 검색 지속/종료를 결정한다. 별도 검색 encoder와 중간 query·종료 텍스트 생성을 줄이는 구조다. [방법 §3](https://arxiv.org/html/2604.17866v2)

| 항목 | 원문에서 확인한 내용 |
|---|---|
| 제어 입력 | 마지막 `[PRED]` token의 last-layer hidden |
| 제어 출력 | 검색 지속/종료 이진값 |
| 실제 head | 단일 affine projection + sigmoid, 파라미터 `d+1` |
| 추가 제어 forward | 추가 LLM forward 없음 |
| 제어 label | 필요한 gold 문서를 모두 회수했는지 |
| 학습 | Next-token·contrastive retrieval·control BCE, backbone 전체 fine-tuning |

본문은 MLP라고 표현하지만 **부록 B.1의 실제 명세는 선형층+sigmoid**다. 따라서 작은 선형 head와 같은 hidden 재사용 자체도 직접 겹친다. [부록 B.1 및 학습 세부](https://arxiv.org/html/2604.17866v2)

## 우리 방식과의 차이

| 비교 축 | LAnR | 현재 우리 프로필 |
|---|---|---|
| 검색 인터페이스 | 학습한 latent retrieval | 기존 keyword/semantic/read API |
| 문서 표현 | 같은 LLM으로 재구성 | 기존 embedding/index 유지 |
| 학습 범위 | Backbone 포함 | Backbone 고정, 작은 head |
| 제어 | 검색/종료 | 3개 도구+FINAL |
| 인자 | 텍스트 검색어를 latent query로 대체 | 같은 LLM이 텍스트 인자 생성 |

이 비교는 원문과 우리 코드의 해석이다. 저자 실험은 재현하지 않았으며 데이터·hardware·pipeline이 달라 점수나 시간을 직접 비교하지 않는다. LAnR의 indexing 비용과 serving 비용도 구별해야 한다. [Serving 설명 및 Appendix B](https://arxiv.org/html/2604.17866v2)

## 우리 연구에 주는 판단

**피해야 할 주장:** 마지막 hidden에 작은 linear head를 붙였거나 추가 forward 없이 제어했다는 사실을 최초 기여로 내세우기.

**검토할 차별점:** 기존 검색 API와 frozen reader를 유지하면서, Native 모방을 넘어 실제 행동별 downstream 품질·비용 차이를 소량 데이터로 학습할 수 있는지. 이는 아직 가설이다. 외부 API 보존이나4-action이라는 설계 차이만으로 충분한 연구 기여가 되지는 않는다.

먼저 학습 없는 optimized Native routing과 비교해야 한다. 차이가 남을 때만 head의 학습 목표·데이터 효율·실패 상태 일반화를 연구하는 것이 타당하다.
