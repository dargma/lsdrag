# FORGE 개별 논문 정리

논문: **FORGE: Form-Optimal Routing of Grounded Evidence for Frozen LLM Agents**. 최초 공개2026-09-28, 검토 버전v1. 2026-10-17에 방법·학습·비용·부록을 확인했다. [논문 페이지](https://arxiv.org/abs/2609.34358v1), [본문](https://arxiv.org/html/2609.34358v1).

## 무엇을 하는가

Frozen host 주변에서 증거 제공 형식과 thinking depth를 결합한 후보를 고른다. 약269K router를 사용하며, 여러 후보의 답변 품질·token cost를 측정한 뒤 Boltzmann 목표로 KL 증류하고 GRPO로 개선한다. **Frozen LLM+작은 router+반사실 후보 평가+품질/비용 학습**이라는 조합이 이미 존재한다. [§2–3](https://arxiv.org/html/2609.34358v1)

| 항목 | 원문에서 확인한 내용 |
|---|---|
| 결정 단위 | 질문별 support form×thinking depth |
| Support form | Direct / Summary / Raw |
| Router 입력 | 외부 query embedding·검색·구조 특징, Full에는 host probe 특징 추가 |
| Stage0 | 1,500 train query×3 arm 평가 |
| Stage1 | 비용 민감 Boltzmann target에 대한 KL 학습 |
| Stage2 | Host feedback 기반 GRPO |

[학습 §3.2, Appendix B.4–B.5](https://arxiv.org/html/2609.34358v1)

## Full과 Lite, Cached와 Fresh를 구분해야 한다

Full은 새 질문에서 routing 전에 host probe4회를 사용하고, Lite는 그 특징을 제외해 재학습한다. Lite도 별도 embedding·검색 특징은 사용한다. Cached 결과에서 probe가 이미 존재하는 경우와 Fresh Online에서 실제 취득하는 비용은 다르다. [Table2, Appendix B.5/B.9](https://arxiv.org/html/2609.34358v1)

저자 Table2의 Qwen3-8B Fresh Online p50은 Raw122.5ms, Lite128.0ms, Full271.4ms다. **Token cost 감소가 walltime 감소를 뜻하지 않는 사례**다. 표의 비용 단위와 raw token 수를 혼동하지 않는다. 수치는 저자 보고이며 재현하지 않았고 우리4B 결과와 직접 비교하지 않는다. [§4.2 및 비용 설명](https://arxiv.org/html/2609.34358v1)

## 우리 방식과의 차이

| 비교 축 | FORGE | 현재 우리 프로필 |
|---|---|---|
| 모델 접근 | Host weight access 없이 외부 routing | Prefill의 내부 hidden 접근 |
| 결정 | 질문별 증거형식·thinking 설정 | 관측이 바뀔 때마다 도구/FINAL |
| 특징 비용 | Full/Lite에 따라 추가 특징 취득 | 이미 필요한 동일 prefill의 hidden 재사용 |
| 학습 목표 | 후보 품질·비용, KL/GRPO | 현재는 Native 행동 모방 CE |
| 반사실 가치 학습 | 있음 | 제안만 있으며 미실행 |

이 차이는 설계 비교이며 독창성 입증은 아니다. 특히 **Lite는 추가 host probe가 없으므로 “FORGE는 항상 여러 LLM 호출이 필요하다”는 비교는 틀리다.**

## 우리 연구에 주는 판단

“Frozen host를 작은 router로 더 잘 쓰게 만든다”는 일반 주장은 충분히 차별화되지 않는다. 남겨 볼 질문은 **이미 얻은 prefill 표현만으로 순차 도구 선택의 미래 품질·비용을 얼마나 적은 branch 데이터로 개선할 수 있는가**다.

구체적으로는 Native 대비 행동별 이득을 학습하고, 확신이 부족하면 기준 정책을 유지하는 제한 개입을 검토할 수 있다. 그러나 반사실 학습·KL anchor·작은 router 각각은 이미 익숙한 요소다. 강한 Native baseline 대비 재현 가능한 개선과 데이터 효율을 보여야 한다. 이 아이디어는 아직 구현·학습·검증하지 않았다.
