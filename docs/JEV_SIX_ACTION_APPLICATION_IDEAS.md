# 여섯 행동의 활용 아이디어 — 미채택 브레인스토밍

2026-10-15 UTC. 이 문서는 **아이디어 목록**이며 현재 head-only 학습·평가 계획을 변경하지 않는다. 새 도메인 데이터 수집, 외부 서비스 호출, 저장·수정·삭제 기능을 승인하거나 구현한 기록도 아니다. 실행 중인 계획은 새 full-tool 상태에서 여섯 행동을 모방 학습하는 작은 pilot이며 world model·surprise·UPR는 포함하지 않는다.

## 먼저 정확히 이해할 현재 여섯 행동

`keyword_search`, `semantic_search`, `read_chunk`, `image_search`, `figure_read`, `FINAL`은 **매 iteration에서 고르는 여섯 선택지**다. 앞의 다섯 개를 차례로 한 번씩 실행하고 끝내는 고정 6단계 workflow가 아니다. 같은 검색을 다른 인자로 반복할 수도 있고, 필요한 evidence가 있으면 일찍 FINAL을 택할 수도 있다. 기능 smoke의 고정 순서는 handler 연결 확인을 위한 시험이었다.

| 행동 | 현재 기능 | 경계 |
|---|---|---|
| keyword_search | 식별자·명칭·구체 용어로 chunk 탐색 | 새 corpus 수집이나 웹 검색 기능이 아님 |
| semantic_search | 의미 기반 chunk 탐색; G1은 text/image ranking 융합 | 결과 순위는 근거의 정확성·충분성 보증이 아님 |
| read_chunk | 원문·표·인접 chunk 정보 및 연결 이미지 읽기 | 영구 문서 수정이 아님 |
| image_search | 실제 pixel embedding으로 figure 후보 검색 | 후보 반환만으로 이미지를 Reader가 보았다는 뜻이 아님 |
| figure_read | 선택한 figure의 실제 pixels와 연결 text 읽기 | 이미지 해석·정답 여부는 별도 모델 능력 |
| FINAL | 답변·인용·필요한 설명을 출력하고 종료 | 외부 지식베이스에 쓰거나 변경을 승인하는 기능이 아님 |

현재 handler들은 corpus를 탐색·읽는 도구다. 읽은 항목·이미지 budget을 내부 실행 상태에 기록하는 것은 영구 지식 관리 기능과 다르다. 지식 등록·수정·병합·삭제·재색인·스케줄 등록을 자동 수행하려면 별도의 tool schema, 권한, 변경 검증, 이력·복구 정책, 새 학습 계약이 필요하다. 지금의 행동 label에 쓰기 의미를 몰래 추가하면 안 된다.

## 활용 후보 여섯 가지

| 후보 | 실제 사용자 질문과 읽기 흐름 예 | 현재 인터페이스로 줄 수 있는 결과 | 추가로 필요한 것 / 실패 위험 |
|---|---|---|---|
| 연구 지식 검색 | “이 주장에 해당하는 실험 조건과 그림을 찾아 달라.” 용어 검색 → 원문 확인 → 필요한 figure 확인 → 추가 문서 검색 | 근거 위치, 실험 조건의 답변, 인용과 미확인 사항 | 최신 논문 수집은 별도 ingestion. 그림 caption만 읽고 실험을 이해했다고 답하거나 여러 논문의 조건을 섞을 위험 |
| 시각 문서 탐색 | “이 부품 배치가 어느 도면에 있고, 설명 문단과 맞는가?” text로 대상을 특정한 뒤 image 후보를 열어 확인 | 관련 figure와 설명, 시각적 속성에 대한 근거 있는 답변 | 작은 글자·축·복잡한 관계를 Reader가 못 읽을 수 있음. 현재 고정 해상도에서 더 비싼 재관측을 자동 선택하는 기능은 없음 |
| 출처·주장 검증 | “이 요약 문장이 본문과 그림 양쪽에서 지지되는가?” 인용 chunk 확인 → 주변 문맥 → figure 확인 → 모순 확인 | 지지/불충분/모순 판단, 실제 확인한 인용 | 발견한 문서의 존재와 주장의 진실을 혼동하지 않아야 함. 관련 이미지가 다른 대상이나 다른 버전일 수 있음 |
| 변경·신선도 점검 | “현재 corpus의 두 버전 사이에서 이 수치가 바뀌었는가?” 버전 식별자 검색 → 두 원문·그림 비교 | corpus에 들어온 두 버전의 차이와 확인 시점 | 외부 원문 변경 감지·다운로드·주기 실행은 미구현. 새 버전이 corpus에 없으면 ‘변경 없음’이 아니라 ‘현재 관측에서 확인 못함’ |
| 유지보수 권고 | “이 지식 문서의 오래된 수치·깨진 출처·서로 다른 설명을 찾아 달라.” 의심 항목을 검색·교차 확인 | 검토할 위치, 근거, 수정 후보 문구 또는 검토 권고 | 실제 수정·삭제는 별도 작업. 문서 미검색을 삭제 근거로 삼거나, 최신성을 확인하지 못했는데 대체 문구를 확정할 위험 |
| entity/관계 확장 | “이 대상과 연결된 기관·제품·원인 관계를 근거와 함께 찾아 달라.” 확인된 entity에서 검색을 확장 | 근거가 있는 후보 entity·관계와 출처 | graph DB 생성·중복 병합·edge 승인 기능은 없음. 동명이인·관계 방향·시점 혼동에 주의. 정형 edge export를 원하면 출력 계약도 별도로 설계 |

이 흐름 예시는 가능한 순서일 뿐 고정 pipeline이 아니다. 실제 정책은 현재 확보한 근거와 남은 budget에 따라 다음 행동을 고른다. G1 search-linked 경로에서 이미 pixels가 전달됐다면 `figure_read`를 의식적으로 반복할 이유가 없을 수 있다. 여섯 클래스 모두를 쓰게 만드는 것 자체는 사용자 가치도 좋은 정책의 조건도 아니다.

## 가장 먼저 좁혀 볼 사용 사례: 문장–그림 근거 검증

**추천 후보는 하나의 기술 문서 묶음에서 “주어진 주장과 인용이 실제 본문·그림에 의해 지지되는가”를 확인하는 읽기 전용 보조기다.** 넓은 지식 관리보다 입력과 완료 조건이 명확하고 현재 도구에 잘 맞는다. 현재 pilot에 즉시 추가하자는 결정은 아니다.

예: 사용자가 “이 부품은 그림 4에서 중앙이 아니라 가장자리에 배치된다”는 문장과 문서명을 준다. 정책은 문서와 figure를 특정하고 필요한 pixels 및 주변 문맥을 확인한 뒤, 지지·모순·판단 불가 중 하나를 근거와 함께 답한다. 이미지 없이 caption만으로 충분한 사례와 실제 pixels를 봐야 구분되는 사례를 분리할 수 있다. 질문에 답이 될 visual attribute를 검색어로 미리 확정해 넣지 않는다.

완료는 단순히 figure를 열었는지가 아니라 **올바른 문서·버전·대상의 근거를 확인하고, 틀린 주장에 동조하지 않았는지**다. 원문 근거가 없으면 판단 불가가 정당한 결과다. 영구 문서 수정은 하지 않는다.

후속 pilot을 별도로 채택한다면 필요한 검증은 작게 한정할 수 있다.

- 같은 corpus·reader·image budget에서 생성형 선택, constrained first-token, learned head의 최종 검증 결과를 비교한다.
- 판단 정확도뿐 아니라 잘못된 대상/figure 인용, 근거 부족인데 확정한 비율, 무의미한 반복 읽기, 조기 종료를 확인한다.
- 맞는 문장과 틀린 문장에 대해 검색 난이도·표현 형식을 맞춘다. head가 문장 형식만으로 답을 구분하지 못하게 한다.
- 문서군을 나누고, 같은 figure의 crop·caption·다른 질문이 train/dev에 동시에 넘어가는지 감사한다.

데이터를 늘리거나 위 범위를 실행하는 것은 별도 선택이다. 지금의 head-only imitation 결과를 기다리는 동안 새로운 benchmark와 쓰기 도구를 함께 만들지 않는다.

## 엔지니어링 가치와 연구 독창성의 구분

엔지니어링 가치는 도구 schema와 handler의 일치, 잘못된 인자 차단, 실제 image 전달, 반복 관측의 추적, 적절한 종료, 사용자에게 검토 가능한 근거 제공에서 나온다. 유용한 제품이 될 수 있지만 그 자체로 새 학습 알고리즘은 아니다.

여섯 분야에 같은 여섯 행동을 붙였다는 사실도 독창성 근거가 아니다. 연구 주장은 **어떤 상태에서 기존 선택기가 실패하고, 어떤 학습 신호나 표현이 같은 정보·데이터·용량 조건에서 그 실패를 줄였는지**가 있어야 한다. 현재 BC pilot은 우선 teacher 행동을 어느 정도 재현하는지와 실제 agent가 제대로 작동하는지를 확인한다. 실패 궤적을 포함한 teacher 행동을 모방하는 것만으로 최적 도구 사용을 배웠다고 할 수 없다.

도메인을 옮겨 재학습했다면 학습 원리의 적용 가능성 또는 적응 결과다. 다른 도구로 zero-shot 전이했다고 부를 수 없다. 새 쓰기/삭제 도구를 추가하면 action 공간·위험·평가가 달라지며 현재 checkpoint를 그대로 사용할 수 없다.

## head 품질과 calibration의 주요 실패

1. **선택 softmax와 정답 가능성의 혼동.** `P(action)`이 높아도 해당 도구가 유용하거나 최종 답이 맞을 확률이라는 보장은 없다. FINAL의 높은 확률을 “근거가 충분하다”로 표시하지 않는다.
2. **teacher의 반복·성급한 종료를 복제.** BC는 유용하지 않은 검색이나 실패 후 종료도 학습할 수 있다. 예측 action 일치율과 실제 완료 품질을 함께 본다.
3. **희소 행동의 형식상 지원.** `image_search`와 `figure_read`가 schema에 있다는 사실은 head가 이 행동을 필요한 때 선택한다는 증거가 아니다. 학습 coverage가 부족하면 여섯 행동 모델로 검증됐다고 보고하지 않는다.
4. **시각 관측의 부재를 확신으로 덮기.** image budget 소진, 작은 이미지·숫자 읽기 실패, 잘못된 entity를 오류 유형으로 남긴다. retrieved·opened·delivered·understood는 같은 상태가 아니다.
5. **변경된 corpus와 도구 계약.** 새 문서의 어휘·배치와 다른 index에서 점수 분포가 바뀔 수 있다. schema/prompt hash 검증만으로 정책의 도메인 성능이 보장되지 않는다.
6. **정지 후 사람의 검토에 대한 오해.** FINAL은 현재 agent의 답변 종료다. 지식 수정 승인이나 외부 사실 검증 완료의 의미를 자동 부여하지 않는다.

별도의 calibrated confidence를 원하면 무엇의 확률인지—도구 실행 성공, 추가 획득의 순이득, 최종 답변 정확성—부터 정의하고 별도 held-out label로 검증해야 한다. 최대 action softmax를 다른 이름으로 보여 주는 방식은 피한다.

## 현재 실행안과의 관계

이 문서의 후보들은 채택되지 않았다. 현재 승인된 순서는 기존 M3 자산을 정확히 복구하고, 새 full-tool 상태에서 사전 고정 split과 행동 coverage를 검증한 뒤, 동일 selection prefix·인자 정책을 사용하는 생성형/first-token/6-action BC head를 작은 pilot에서 비교하는 것이다. 옛 Q3 결과를 재사용하지 않으며 shared GPU 기능 실행에서 비교 속도를 주장하지 않는다.
