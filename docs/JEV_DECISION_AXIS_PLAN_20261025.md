# 바닐라 A-RAG가 못 하는 결정을 selection head로 — 빠른 POC 계획 (2026-10-25)

**축:** 바닐라 A-RAG에는 FINAL 결정 지점이 없다(텍스트 응답 = 종료). head는 답을 생성하기 전에 멈춤을 결정하고, 그 순간 이력을 지우고 깨끗한 컨텍스트로 답할 수 있다(E0에서 F1 +6~8pp). 이 차이로 "더 적은 입력에 같거나 더 나은 정확도"가 나오는지 감을 본다.

**원칙:** 엄밀성보다 속도를 우선한다. 이상하면 바로 버린다. 숫자는 대략적인 방향만 본다.

**고정:** Qwen3.5-9B, 공유 코퍼스, base 정책 value_aux. **R** = FINAL 시 `질문 + 본 chunk`로 다시 답하기(E0 방식).

## 1단계: 기존 train48 분기 데이터로 오프라인 확인 (GPU 약 15분)

317개 상태마다 R 답변을 하나씩 만들고("지금 멈추고 정리해서 답하면 맞나"), 아래를 대충 계산한다.

| 아이디어 | 볼 것 | 계속할 조건 (대략) |
|---|---|---|
| ② 정보 가치 멈춤 | "지금 답하면 맞을 확률"과 "한 번 더 하면 맞을 확률"의 차이로 멈추면 EM과 입력이 어떻게 되나 (probe) | 입력이 크게 줄고 EM이 거의 유지 |
| ③ 루프 감지 | 새 chunk가 안 나오거나 query가 반복되면 바로 R → 결과 | 상한 걸린 문항에서 토큰 절감 |
| ⑦ 답 초안 신호 | R 답변 logprob을 probe에 추가하면 예측이 좋아지나 | AUC가 눈에 띄게 상승 |
| ⑥ 포기 | "이 문항은 틀릴 것" 예측이 쓸 만한가 | AUC .70 근처 이상 |
| ⑤ 갈래 실행 | 애매한 상태에서 두 branch 중 확신 높은 쪽을 고르면 EM이 오르나 | EM이 오르고 비용이 조금 늘어남 |

## 2단계: 살아남은 것만 작게 실제 실행 (GPU 1~2시간)

- train 문항 약 64개에서 value_aux를 돌리며 라벨을 모으고, 작은 head를 학습한다(CPU, 몇 분).
- ④ 홉 인지 선별은 2단계 결과가 좋을 때만 붙인다(chunk hidden 수집 필요).

## 3단계: 비교 한 번 (GPU 2~3시간)

reserved80 중 일부(약 40문항)에서 네 조건을 비교한다.

| 조건 | 설명 |
|---|---|
| 바닐라 A-RAG | FINAL 없음, 텍스트 응답이 종료 |
| 바닐라 + 재답변 | 텍스트 응답을 감지하면 R |
| 우리 native | FINAL 포함 |
| head + R | 임계값 2~3개 |

EM, F1, 입력 토큰, 호출 수를 표로 정리하고 끝낸다.

## 구현 작업

1. 바닐라 모드: FINAL을 빼고 텍스트 응답을 종료로 처리한다.
2. R 함수 공용화(E0 코드 재사용).
3. 1단계 스크립트 하나.
