# 실험 결정 기록

## 2026-10-13

- 최초 결정은 이미지 관련 200개였으며 이후 100개를 거쳐 최신 결정으로 최종 50개로 축소했다. 개발 질문은 분리한다.
- V2 도구·프롬프트·탐색 흐름 재설계를 허용한다. 효과 해석은 인터페이스 묶음 변경으로 한정한다.
- 사용자 요청에 따라 추가 승인 없이 판단 근거를 기록하며 진행한다.
- A-RAG `a44de6b2216bf6791979c4b6ac4ae106212fa1a6`의 전체 소스 검색과 `configs/example.yaml` 확인 결과 rerank 구현·설정이 없으므로 필수 실험은 rerank 없이 실행한다.
- Reader의 축소를 허용하되 네 실험에는 동일 모델을 적용한다. 실제 모델은 실행 가능성과 개발 검증을 거쳐 고정한다.
- 최초 자원 조회: NVIDIA RTX PRO 6000 Blackwell Server Edition, 전체 97,887 MiB, 가용 79,148 MiB. 로컬 디스크 가용 약 39 GiB. 이는 조회 시점 값이며 실행 전 재확인한다.
- 원래 Reader 및 전체 PDF의 로컬 보관 가능성은 아직 확인되지 않았다. 모델 다운로드 전 파일 용량·기존 캐시·접근 권한을 조사한다.

## 사전 확인 후 확정

- 26B Reader는 가중치만 48.07GiB여서 현재 로컬 저장 공간에 맞지 않는다. 14.89GiB인 Gemma 4 E4B를 내려받고 native 도구 호출과 실제 이미지 인식을 검증했다.
- 이미지 전달은 tool 결과 뒤 user 이미지 메시지를 사용한다. vLLM 0.20의 tool-role 이미지 오류와 후속 캐시 오류를 재현했으며 멀티모달 처리 캐시를 비활성화했다.
- 임베딩, Reader, 파서 환경을 분리한다. 각각 Transformers 5.19.0, 5.6.2, 5.18.0을 사용한다. 실제 실패와 성공 근거는 사전 확인 보고서와 smoke JSON에 보존한다.
- 평가 후보는 이미지 근거가 명시된 940개 중 200개이며, 개발 50개와 근거 문서 URL도 겹치지 않는다. 수집 QC가 끝나기 전에는 최종 데이터 유효성을 확정하지 않는다.
- MinerU의 원문 캡션과 주변 문맥을 평가하기 위해 image_analysis=False를 공통 적용한다. 모델이 생성한 이미지 설명을 B0에 조용히 추가하지 않는다.
- advanced tier의 초기 1페이지 파싱은 느려 표준 hybrid tier의 품질과 처리량을 검증한다. 파서 모델은 지정된 2604 revision으로 유지한다.


## 2026-10-13 보조 대화의 최신 사용자 결정

- M3DocVQA 최종 평가는 이미지 근거 관련성이 높은 100문항으로 변경한다. 기존 200개 후보는 선정 이력이며 최종 manifest를 100개로 재고정해야 한다.
- Mem-Gallery 보조 60문항(VS 30, VR 30)을 추가한다. B0/V1/V2와 정답 근거 직접 제공 Reader 진단을 비교하고 질문 이미지 유무를 분리한다. 데이터 스키마와 공식 평가 코드는 실행 전에 확인한다.
- 사용자가 계획 업데이트와 추가 승인 없이 계속 진행할 것을 명시했다. 현재 개발 실행을 중단하거나 다시 시작할 필요는 없다.
- 본 변경은 계획·상태 기록에 반영한 것이며 실제 질문 manifest나 실행 결과를 변경하지 않았다. 다음 평가 준비 단계에서 실행 입력과 계획의 일치를 확인한다.

## 최신 변경 — 두 벤치마크 각각 50문항

- 사용자 지시에 따라 M3DocVQA 이미지 중심 최종 평가 50문항, Mem-Gallery 최종 평가 50문항(VS 25, VR 25)으로 확정한다. 위의 100/60문항 결정은 변경 이력으로만 보존한다.
- 비교 조건과 정답 근거 직접 제공 Reader 진단은 유지한다. 개발 집합은 평가 집합과 분리한다.
- 이번 수정은 계획과 상태 기록이며 실행 입력 manifest는 본 평가 전에 새 범위로 확정해야 한다. 기존 실행과 결과는 수정하지 않는다.
