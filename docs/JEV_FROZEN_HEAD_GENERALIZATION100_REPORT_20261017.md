# Frozen 도구 head 일반화 평가 보고서

작성일: 2026-10-17 UTC. 현재 결과를 저장하고 추가 실험을 중단한다는 사용자 지시를 반영했다. 후속 head 재학습·3-hop 평가·RL·새 인자 decoder는 실행하지 않았다.

## 결론

**학습한 head로 도구를 선택하고, 같은 LLM이 인자를 이어 생성하는 구조는 실제로 동작했다.** 사전 동결한 새 2-hop 100문항에서 Native와 비교했을 때 F1·EM 점추정은 소폭 높고 생성량과 관측 episode 시간은 낮았다. 작은 20문항 파일럿에서 관측한 방향이 더 큰 문항 집합에서도 반복됐다는 실용적 가능성이 있다.

다만 품질 개선·통계적 비열등성·통제된 속도 향상·논문 독창성을 입증한 것은 아니다. 도구 선택 head와 aligned/cache 실행 경로가 함께 바뀌므로 각 요소의 기여를 분리해 해석해야 한다.

## 평가 계약

- 모델: Qwen3-4B-Instruct-2507, non-thinking, greedy. Backbone과 기존 v3 head를 고정했다.
- 행동: `keyword_search`, `semantic_search`, `read_chunk`, `FINAL`. 텍스트 입력만 사용했다.
- Native는 전체 도구 호출·인자·최종 답변을 생성한다. Head 조건은 head가 도구를 고르고 기존 cache에서 같은 LLM이 인자·답변을 생성한다. 인자 후보 선택은 사용하지 않았다.
- 이전에 노출되거나 예약된 질문과 공유 하위 질문을 가용 기록에서 감사해 제외했다. 답변 가능한 dev 2-hop 1,252문항 중 1,099문항이 남았고, outcome-blind hash 순서로 100개를 고르면서 새 집합 안의 하위 질문 중복도 제외했다. 100문항의 하위 질문 200개가 서로 다르다.
- 질문마다 두 조건의 실행 순서를 교대했다. 총 200 episode를 모두 완료했다. 출력 상한512/context16,384/최대8 tool calls+FINAL을 유지했다.
- 정답·근거는 채점에만 사용했다. 새 100문항의 결과에 맞춘 학습·프롬프트 수정·샘플 교체는 없었다. 이 평가를 추후 튜닝용 validation으로 재사용하지 않는다.

공개 데이터에 대한 모델의 사전학습 노출까지 배제할 수는 없다. family 중복 배제로 선택된 집합의 분포는 원 dev 전체와 다를 수 있다.

## 주 결과

평균값은 문항당 값이다. 오류 문항도 모두 포함했다.

|---|---:|---:|
| 답변 F1 | 31.11% | 31.57% |
| EM | 19.00% | 20.00% |
| 근거 F1 | 39.23% | 40.07% |
| 실제 tool calls | 2.26 | 2.39 |
| Interaction turns — 종료·실패 시도 포함 | 3.26 | 3.39 |
| 생성 토큰 | 94.32 | 60.81 |
| 별도 강제 구문 토큰 | 0.00 | 31.07 |
| 입력 토큰 — head의 강제 구문 포함 | 3,914.01 | 4,106.24 |
| Decoder forward 수 — 기록에서 산출 | 91.06 | 59.81 |
| 평균 episode 시간 | 1.337초 | 0.978초 |
| 100문항 시간 합계 | 133.662초 | 97.833초 |
| 오류 episode | 4 | 0 |

관측 시간 비율 Native/head는 **1.366배**, 시간 감소율은 **26.8%**다. 순차 생성 토큰은35.5% 줄었다. 생성+강제 구문은94.32→91.88이지만 입력 토큰은4.91% 증가했다. 입력과 강제 구문을 중복 합산하거나, 토큰 총합을 그대로 FLOPs로 해석하면 안 된다. 실제 도구 호출과 interaction은 감소하지 않았다.

F1 기준 **5승·90동률·5패**다. Native가 맞힌 exact 정답3개를 잃었고 새 exact 정답4개를 얻었다. Paired F1 차이는+0.457%p이고 descriptive bootstrap95 구간은[-4.938, +5.957]%p다. EM 차이+1.0%p의 구간은[-4.0, +6.0]%p다. 따라서 평균 점추정이 비슷하다는 것과 품질 동등성이 입증됐다는 것은 다르다.

## 시간 이득이 크게 나타난 이유

도구 이름 몇 단어만이 아니라 `<tool_call>`·이름 필드·JSON 틀을 포함한 호출당 약13토큰의 고정 구문을 런타임에서 일괄 처리한다. 문항당 호출이2~3회여서 약30토큰의 순차 생성이 대체된다. 고정 구문 뒤의 인자 값은 여전히 LLM이 생성한다. 인자 생성을 위해 전체 문맥을 다시 prefill하지 않고 기존 KV cache를 이어 사용한다.

| 측정 구간 / 문항 | Native | Head |
|---|---:|---:|
| Prefill | 0.1448초 | 0.1477초 |
| 강제 구문 일괄 처리 | 0 | 0.0418초 |
| 순차 decoding | 1.1438초 | 0.7438초 |
| 도구 실행 — query embedding 포함 | 0.0150초 | 0.0144초 |
| 그 밖의 episode 처리 — 차감 산출 | 0.0330초 | 0.0307초 |

Native 전체 시간의 약85.6%가 decoding이었다. 토큰마다 큰 모델을 거치는 순차 계산을 줄이면서 decoding 관측 시간이 약0.400초 줄고, 일괄 구문 처리에는 약0.042초가 들었다. 전체 차이 약0.358초와 정합적인 내역이다.

이것은 각 실행 경로의 timer 집계이며 고정된 동일 도구·인자·답변에서 요소 하나만 바꾼 인과 분리 실험은 아니다. 모델 로딩·문서 사전 embedding·채점·파일 저장은 episode 시간에서 제외했다. 검색 query embedding과 계측용 tokenization은 포함했다. 공유 GPU와 순서·warmup·trajectory 차이 때문에 1.366배를 보장된 제품 속도나 통제된 speedup으로 표현하지 않는다.

## 품질과 형식 안정성의 기여

Native 오류4건 중1건은 잘못된 JSON이고3건은 모델이 답변 schema 대신 `error` 객체를 출력한 경우다. 모델의 “잘못된 질문” 주장은 데이터 결함의 검증 결과가 아니다. Head의 schema 경로에서는 해당 형식 오류가 없었다. 그4문항 중1문항에서 head가 정답을 얻었다.

사후 보조 분석으로 양쪽 오류가 없는96문항만 보면 F1 차이는 **-0.565%p**, EM 차이는0%p다. 주 분석은100문항 전체이며 이 subset으로 결과를 대체하지 않는다. 작은 전체 점수 우위를 도구 선택 능력 향상 하나로 설명할 수 없다는 점을 보여준다.

처음 도구 궤적이 갈라지는 지점은 행동29문항, 인자11문항, head가 더 진행5문항, 더 일찍 끝남3문항이었다. 나머지52문항은 도구·인자·결과 궤적이 같았다. 종료 차이는 format failure도 포함할 수 있어 곧바로 성급한 종료라고 이름 붙이지 않았다.

대표적인 손실 사례는 `2hop__91626_96912`와 `2hop__123145_80420`이다. 같은 앞선 관측에서 Native는 semantic search, head는 read를 골랐고 Native 정답이 head에서는 오답으로 바뀌었다. 반대로 keyword/semantic 선택 차이로 head가 새 정답을 얻는 경우도 있었다. 이 사례는 후보 원인 분석이며 최적 도구 label의 검증은 아니다. 세부 qid·답변·분기는 JSON에 보존했다.

## 앞선 진단과의 관계

인자 선택 ON/OFF는 별도의 기존20문항에서 read15회 중8회 생성을 생략했지만 F1 30.43%→25.43%, EM25%→20%로 떨어졌다. 따라서 이번100에서는 인자를 항상 생성했다.

Interaction 축소 진단은 별도의 노출된 train24/validation8 상태에서 진행한 oracle 상한 분석이다. 중간 단계 대체의 학습 gate는 통과하지 못했고, 관측된 단축은 조기 종료로도 설명됐다. 이번100문항의 시간 이득은 interaction 축소 성공을 뜻하지 않는다.

## 저장 위치와 보류 상태

### Native가 정확도 상한인가

Native의 행동을 hard label로 모방하는 현재 학습은 기본적으로 Native를 저렴하게 근사하는 목표다. 모든 상태에서 행동뿐 아니라 인자·답변 실행 경로까지 완전히 같아진다면 같은 결과를 낸다. 그러나 Native가 최적 정책이라는 보장은 없으므로 Native의 QA 정확도가 절대 상한은 아니다. 형식 오류 방지나 다른 행동 선택으로 head가 더 맞힐 수도 있고 더 틀릴 수도 있다.

Head는 마지막 토큰의 hidden vector 하나를 읽는다. Native의 순차 생성은 전체 KV cache를 계속 참고하며 추가 계산한다. 같은 backbone이라는 사실만으로 두 제어 경로의 능력이 동등하거나 마지막 hidden의 작은 linear readout이 Native 정책을 항상 표현할 수 있다는 결론은 나오지 않는다. 현재 결과의 작은 점수 차이를 체계적 정확도 향상으로 주장하지 않는다.

### Native보다 좋은 trajectory를 학습하려면 — 미실행 후속 아이디어

Native의 행동을 정답이 아닌 후보 하나로 두고, 같은 공개 관측 상태에서 합법 행동들을 실제 실행하여 새 suffix의 정답·근거·남은 비용을 측정한다. 다음 두 목표를 구분할 수 있다.

1. **개선된 행동 label 증류:** 품질을 유지하는 시험 경로 중 더 저렴한 경로의 첫 행동으로 head를 학습한다. 동률과 관측 근거를 함께 처리하고 빠른 오답은 긍정 label로 삼지 않는다.
2. **행동별 가치 예측:** 각 행동의 예상 품질과 미래 도구·생성 비용을 별도로 예측하고, 품질을 우선하는 비용 제어 정책으로 선택한다. 단순 teacher 행동 일치가 아니라 실제 downstream 차이를 목표로 한다.

개선 정책이 만든 새로운 상태에서도 다시 후보를 비교하는 정책 개선 반복이 필요하다. 고정된 후속 정책으로 측정한 행동 가치는 그 후속 정책에 조건부인 값이며 전역 최적 가치가 아니다. 제한된 action·argument 후보의 최선도 전역 최적 trajectory를 보장하지 않는다. 미래 결과는 학습 label 계산에는 사용할 수 있지만 inference feature·호출 인자에 몰래 넣어서는 안 된다. 이때부터 Native는 목표의 절대 상한이 아니라 비교 기준이 된다.

이번 반사실 probe는 그 데이터를 만들기 위한 제한 진단이었다. 현재 작은 자료에서 중간 단계 압축 후속 gate가 실패했으므로 가치 head·정책 반복·RL 학습은 실행하지 않았다. 새100 평가 문항은 이러한 학습에 사용하지 않는다. 모든 후속 아이디어는 사용자 보류 지시 아래에 있다.
