# Decision head: 목적, 검증 단계와 확장 baseline

날짜: 2026-10-23. 상태: 연구 방향 및 후속 실험 제안 저장. 이 문서는 새 실험 실행 승인이나 완료 기록이 아니다. 현재 A-RAG 검증을 먼저 진행하며 메모리 확장은 별도 제안으로 유지한다.

## 목적과 기여 가설

목적은 제한된 비용에서 필요한 근거를 확보하고 정확한 답을 내는 것이다. Head 자체나 호출 수 감소가 최종 목적은 아니다. 같은 생성 모델의 표현을 활용하는 작은 head가 상태에 맞는 결정을 내리고, 필요한 인자와 답변은 기존 모델이 생성하는 구조의 품질·비용 효과를 검증한다. 단순 검색 파이프라인으로 충분하다면 복잡한 정책을 도입할 근거가 약하다.

기능적 호출 성공, 미래 결과를 고려한 정책 품질, 다른 작업으로의 전이는 별개의 증거다. A-RAG에서 head가 동작하면 확장 실험의 구현 근거가 되지만 메모리 관리로의 전이 성능이 입증되는 것은 아니다. 도구/상태/보상 정의가 달라지므로 같은 설계를 재사용하더라도 새 데이터와 head 학습 또는 적응이 필요할 수 있다.

## A-RAG에서 먼저 검증할 순서

1. **행동 가치와 데이터 품질:** 같은 상태에서 합법적인 다른 행동을 수행하고 이후 실제 답변 정확도와 전체 비용을 비교한다. 기존 분기 자료를 우선 점검하고, 행동 간 결과 차이·표본 잡음·reference 정책 의존성을 구분한다. 동일 상태 반복과 독립 수집 seed가 중요하다. 과거 사후 중요상태 순위를 새 상태 선택의 성공으로 해석하지 않는다.
2. **작은 데이터 보강:** 무조건 문항 수를 늘리기보다 근거 부족/충분, 추가 검색 필요, 읽을 후보 선택, 종료 시점 등의 상태 및 행동 coverage를 확인한다. 미래 정답을 입력에 넣지 않는다. 상태 선택 방식도 uniform 또는 단순 규칙과 같은 수집 예산으로 비교해야 한다.
3. **읽는 표현 비교:** last-token을 기준으로 question-end, observation-end, 구간 pooling, 후보별 표현을 같은 split·학습 목표·데이터로 비교한다. 모방 정확도뿐 아니라 실제 rollout QA와 비용을 평가한다. 마지막 토큰은 앞 문맥에 attention하므로 마지막 위치만 읽는다는 것이 마지막 단어만 본다는 뜻은 아니다.
4. **head 구조 비교:** linear → 작은 MLP → 후보를 구분하는 pooling/attention 순서로 복잡도를 늘린다. 파라미터 수와 추가 연산을 기록한다. action head와 candidate/read-slot 선택의 역할을 분리해 ablation한다. 이미 본 평가셋에서 최적 구조를 고르지 않는다.
5. **학습 목표 비교:** teacher BC, outcome 기반 soft CE, action-value 회귀, return 기반 정책 학습을 같은 수집 자료/예산에서 비교한다. Outcome CE도 미래 결과를 학습할 수 있다. PPO/GRPO라는 이름 자체가 정책성을 증명하지 않는다. PPO는 확률비·clip·advantage 및 행동 변화, GRPO는 같은 시작 조건의 rollout 그룹·보상 분산·추가 수집 비용을 확인한다. 둘을 모두 바로 실행하지 않고 작은 비교에서 다음 방식을 선정한다.
6. **동결 평가:** validation으로만 설정을 정하고 새로운 평가 질문에서 native A-RAG, 단순 고정 검색, BC head, 종료만 학습한 head, 전체 정책 head를 비교한다. 같은 답변/인자 생성기를 사용한다. 독립 수집·학습 seed 반복, paired 품질 차이와 불확실성, 전체 토큰/호출/실패를 보고한다. 공유 GPU 시간은 통제 속도 향상 주장에 사용하지 않는다.

우선 실행 후보는 기존 분기 자료의 신뢰성 점검과 독립 반복 설계다. 데이터·표현·구조·RL 알고리즘을 동시에 바꾸지 않는다. 구체적인 예산, split, 주조건, 실패 기준을 실행 전에 별도 protocol로 고정한다. 과거 노출된 test는 학습·튜닝에 사용하지 않는다.

## 정책으로서 보여야 하는 행동

- 같은 질문이라도 확보된 근거와 남은 비용에 따라 검색/읽기/종료가 달라진다.
- 추가 행동의 미래 이득이 비용보다 클 때 계속하고, 충분할 때 종료한다.
- 단순 turn 수, 항상 검색, 항상 종료 같은 규칙으로 설명되는 개선인지 확인한다.
- 행동 선택 변화가 실제 답변 품질과 전체 비용에 연결된다. 선택 정확도나 합법적 JSON만으로 판단하지 않는다.
- 출력 pi(a|s)는 행동 분포이지 정답 확률이 아니다. 성공확률이나 행동 가치가 필요하면 별도 target과 calibration 평가가 필요하다. 엔트로피만으로 탐색 가치를 단정하지 않는다.

형식적으로 목표는 J(pi)=E[답변 품질 - lambda * 전체 비용]로 둘 수 있으나 품질과 비용을 따로 보고하고, 품질 하락으로 얻은 비용 절감을 성공으로 포장하지 않는다. A-RAG에서는 현재 episode 결과가 중심이고, 메모리에서는 이후 여러 질문의 결과까지 평가 horizon이 늘어난다. 세부 학습 수식은 [기존 수식 문서](JEV_DECISION_POLICY_MATH_20261023.md)를 참고한다.

## 메모리·지식관리 baseline 제안

| 비교군 | 구현 | 검증 질문 |
|---|---|---|
| 최근 문맥 | 장기 메모리 없이 최근 문맥만 사용 | 장기 기억 자체가 필요한가? |
| 기록 누적+검색 | 원문·출처·시각을 보존하고 hybrid 검색 | 적응적 관리 없이 충분한가? |
| 규칙 기반 관리 | 중복 제거, 버전 관리, 예산에 따른 보존/검색 | 학습된 결정이 필요한가? |
| LLM 직접 판단 | 같은 backbone이 추가/갱신/보류를 생성 | 생성형 결정 대비 head의 효과는? |
| BC head | 같은 관측·행동으로 teacher 선택 학습 | head 구조 자체의 효과는? |
| 미래 성과 학습 head | 이후 QA와 비용으로 결정 학습 | 장기 결과 학습의 추가 효과는? |
| 기존 학습형 방법 | Memory-R1 또는 Mem-alpha의 적합한 비교 | 기존 RL 메모리보다 나은 점은? |

먼저 저장 정책과 활용 정책을 분리한다. 저장 실험은 검색/답변기를 고정하고 추가·갱신·보류만 바꾼다. 활용 실험은 메모리와 후보를 고정하고 무엇을 읽고 추가 탐색할지 바꾼다. 기억 내용 생성기도 동일하게 두어 선택 효과와 문장 생성 효과를 구분한다. 새 기록이 반드시 옳다는 가정은 하지 않고 출처·시각·버전을 보존한다.

주 비교는 같은 저장량·검색 후보·입력 예산·모델로 한다. 기록 누적이 예산을 초과하면 고정 eviction 규칙을 적용하고, 무제한 저장/전체 기록 조건은 별도 진단으로 둔다. 정답 근거를 제공하는 oracle 역시 공정한 예산 baseline과 분리한다. 쓰기·추출·요약·갱신 비용까지 모두 센다.

평가: 미래 QA 정확도, 근거 일치, 오래된 사실에 의한 오류, 잘못된 갱신/삭제, 필요한 기억 손실, 전체 토큰·시간·저장량. 평가 스트림은 시간순이며 writer에게 미래 평가 질문이나 정답을 공개하지 않는다. 사용자/대화 단위로 split을 분리한다.

판정: 기록+검색으로 충분하면 적응적 정책 필요성은 약함. LLM 관리가 도움이 되고 head가 그 효과를 적은 총비용으로 유지하면 효율적 결정 구조의 기여 후보. 동일한 설계가 재학습 후 다른 작업에도 통하면 설계 확장성의 증거이며, 재학습 없는 zero-shot 전이와 구별한다.

## 선행연구와 주장 범위

- [Memory-R1](https://arxiv.org/abs/2508.19828): ADD/UPDATE/DELETE/NOOP와 답변 단계 메모리 활용을 outcome RL로 학습한다.
- [Mem-alpha](https://arxiv.org/abs/2509.25911): 순차적 메모리 구성을 이후 QA 정확도 보상으로 학습한다.
- [MemoryAgentBench](https://arxiv.org/abs/2507.05257): 정확한 검색, test-time learning, 장거리 이해, 선택적 망각을 평가한다.

따라서 미래 질문의 성과로 메모리 결정을 RL 학습한다는 것 자체는 새로운 기여가 아니다. 위 원문들은 비교 설계 참고이며 재현 완료나 우리 head의 우월성 증거가 아니다. 메모리 확장은 A-RAG 정책 검증 이후의 별도 실험 후보로 둔다.

## Hidden head의 미래 결과 예측 가설

Hidden은 현재 관측의 표현이며 미래를 보장하지 않는다. 행동별 Q(h,a)=E[R | 현재표현h, 행동a, 이후 reference정책]를 실제 suffix 결과로 학습하면 기대 결과를 추정하는 작은 head를 만들 수 있다. Q는 이후 정책·환경·보상 정의에 조건부이며 정책이 바뀌면 target도 달라질 수 있다. pi(a|h)는 행동선택 확률로 성공확률과 다르다. 성공확률 예측이 필요하면 binary outcome target과 held-out calibration/Brier score를 별도로 검증한다. Q예측은 held-out value error, 행동 순위와 선택 후 실제 regret/QA·비용으로 평가한다.

현재 suffix 반복 실험은 target 신뢰성을 확인하는 단계이며 미래 예측 head의 일반화 능력 검증 자체는 아니다. 표현에 정보가 부족한 경우 question/observation/candidate 표현 비교가 필요하고, MC잡음이 큰 경우 더 복잡한 head만으로 해결되지 않는다. 관측되지 않은 외부 정보나 우연한 사건을 결정적으로 예측한다는 주장은 하지 않는다.

고정된4action에서는 h→[Q(h,a1),...,Q(h,a4)]처럼 출력축이 행동을 구분하므로 별도 행동 입력이 필수는 아니다. 가변 문서/도구 인자 후보에서는 Q(h,e(candidate)) 또는 state-candidate attention이 자연스럽다. 마지막 hidden은 causal attention으로 앞 문맥을 반영하지만 충분통계라고 가정할 수 없으므로 last vs 구간 pooling vs candidate 표현을 같은 target/data로 검증한다. 행동 종류의 Q는 이후 인자 생성정책까지 평균한 값이며, 구체적인 query/document 선택의 가치는 별도 후보 조건화가 필요할 수 있다.
