# jev_v1.0 — 기여 가설과 검증 계획

2026-10-14 · **아직 검증하지 않은 연구 가설**. 단순히 Gemma에 classifier를 붙였다는 사실을 새로운 알고리즘 기여라고 주장하지 않는다. 최신 decision 모델·agentic memory 연구와 비교해, 증명할 수 있는 차이를 아래처럼 정의한다.

**핵심 가설:** 같은 멀티모달 Reader에서 행동 결정을 저렴하게 만들면, 절약한 계산을 근거의 충분성·상충·탐색에 재배분해 같은 시간 안에 더 신뢰할 수 있는 답을 얻을 수 있다. 저장·수정에서는 빠른 결정의 빈도를 늘리되 출처와 되돌릴 수 있는 기억 전이를 함께 관리한다.

**이번 실행 범위:** 아래 가설 중 **C1의 B-HF vs D-head 두 조건만** 수행한다. C2–C5는 contribution 후보를 보존한 backlog이며 실행 계획이나 추가 비교군이 아니다. 새 M3 20문항 × 두 조건의 작은 PoC 후 근거가 있을 때 확장한다. [Astra 재검토 후 최소 계획](JEV_EXPERIMENT_PLAN.md)

## 1. 기존 관찰이 말해주는 것

현재 M3DocVQA 100문항에서 EmbeddingGemma 2 텍스트+이미지 검색은 이미지 전달 recall 54.3%(검증된 70문항), EM 7%였다. 반환된 이미지 연결 결과의 전달 누락은 0건이었다. 따라서 ‘이미지를 안 넣어서 틀린다’는 경로는 이미 수정됐고, 남은 실패에는 **검색 자체의 누락과 Reader의 해석·선택 오류**가 함께 있다.

같은 모델이 똑같은 상태를 더 빨리 분류한다고 정보가 새로 생기지는 않는다. 단순 teacher 행동 모방만으로 teacher가 못 풀던 문제를 해결했다고 주장할 수도 없다. 아래 기여는 추가 제어 신호·증거·탐색과 결합했을 때에만 검증한다.

## 2. 주장할 수 있는 기여와 기존 아이디어의 구분

| 항목 | 기존 연구에 이미 있는 것 | 우리 조합에서 검증할 차이 |
|---|---|---|
| 직접 행동 결정 | Jev·Kev·Laya·SemIf 등의 bounded decision | **현재 이미지 포함 Gemma Reader**의 같은 상태·같은 backend에서 선택·인자·답변 비용을 분해 |
| 적응형 검색·종료 | adaptive/corrective RAG, confidence gating | 원시 head confidence가 아닌 **근거 충족도·상충도**를 별도 학습해 이미지 근거 탐색을 제어 |
| 계산 재배분 | 다중 경로 탐색·test-time compute | **같은 wall-clock 예산**에서 추가 근거 확인이 실제 정답 회복에 기여하는지 측정 |
| 기억 갱신 신뢰성 | TrustMem 등의 transition verification | 원본 이미지·캡션·시간·출처를 보존하는 **멀티모달 기억 전이 결정**의 오류와 비용 검증 |

정확한 선행연구 범위와 최신 자료는 [Astra 연구 메모](JEV_MEMORY_RESEARCH_ASTRA.md), 학습 구현의 근거는 [decision 학습법 리뷰](JEV_DECISION_MODEL_TRAINING_REVIEW.md)에 연결한다. ‘최초’라는 표현은 사용하지 않는다.

## 3. C1 — 같은 Reader의 선택·생성 분리와 실제 비용 검증

**가설:** Gemma의 동일 forward에서 행동 head와 native 인자 생성을 연결하면, 툴 선택을 텍스트로 생성하는 일부 비용을 줄일 수 있다.

주 비교는 같은 HF backend의 원래 툴 생성과 head 경로다. Reader·이미지·검색·iteration을 유지하고, head·강제 prefix·인자 생성·중복 prefill·fallback까지 포함한 전체 시간을 비교한다. 기존 vLLM과 다른 backend를 비교한 속도 차이를 기여로 세지 않는다.

**입증 조건:** 품질 차이와 불확실성을 공개하면서 총 풀이 시간 감소를 관찰해야 한다. 분류 정확도·출력 토큰 감소만으로 입증되지 않는다. 현재 train 성공 라벨 15턴·read 양성 0으로는 학습 동작 진단을 넘는 결론을 내리지 않는다.

## 4. C2 — 빠른 근거 충족 검사로 성급한 종료·헛도는 검색 줄이기

**실패 유형:** 근거 이미지가 들어왔지만 질문의 위치·개수·관계를 확인하지 않고 답하거나, 이미 본 자료를 반복 검색한다.

현재 상태에서 `ANSWER / NEED_MORE / CONFLICT / INSUFFICIENT` 같은 **근거 상태**를 판별하고, 부족한 관계가 있으면 다음 검색·읽기로 연결한다. 행동 head의 FINAL 확률을 그대로 근거 충분 확률로 대체하지 않는다. 각 판단에는 질문·현재 근거만 넣고 gold는 주지 않는다.

**라벨:** 같은 상태에 대해 핵심 근거 제거·상충 근거 삽입·정답 대상 바꾸기 등의 반사실적 쌍을 train에서 생성하고, 실제 정답 여부·근거 지지를 확인한다. 단순 문구나 특정 사진을 외우지 않도록 원본 질문·문서 단위로 분리한다. 합성 artifact만 배운 효과는 별도 점검한다.

**최소 비교:** 원래 A-RAG / 고정 1회 검증 생성 / decision 근거 검사. 같은 max iteration 조건과 같은 전체 시간 예산 조건을 각각 비교한다. EM·근거 충족 오류·상충 답변·검색 중복·총 시간과 ‘원래 오답→정답’ 문항의 근거 변화를 함께 본다.

## 5. C3 — 절약한 시간을 대안 근거 탐색에 재투자

**실패 유형:** 첫 검색이 관련 문서의 다른 대상을 찾고, 그 가설에 고정되어 답한다. Aria에서 고양이 본문을 읽은 경로가 예다.

질문·실제 검색 결과에서 만든 대안 검색어·후보 청크 중 어디를 더 확인할지 결정한다. 빠른 제어는 두 번째 가설을 검사할 여유를 만들 수 있지만, **후보 생성·추가 검색·이미지 인코딩·Reader 검증은 여전히 비용**이다.

**최소 비교:** 동일 wall-clock 예산에서 단일 경로 / 항상 2개 경로 / 예산을 배분하는 decision 제어. 추가 검색과 이미지 budget을 기록하고, 맞힌 문제만 골라 비교하지 않는다. 후보에는 gold 답·gold figure·teacher의 미래 검색어를 넣지 않는다. beam oracle이나 최선의 최종 답을 사후 선택하는 방식은 실사용 성능과 분리한다.

**입증 조건:** 시간 예산을 늘리지 않고 정답 회복이 증가하며, 어떤 추가 근거가 회복에 필요했는지 설명할 수 있어야 한다. 단순히 더 많은 모델 호출을 사용해 얻은 개선은 ‘빠른 decision의 효과’로 단정하지 않는다.

## 6. C4 — 출처·시간을 보존하는 기억 저장·수정 제어

**실패 유형:** 저장해야 할 사실 누락, 오래된 사실을 최신 사실로 착각, 잘못된 병합, 이미지 요약의 환각이 이후 검색에 반복 반영된다.

`STORE / LINK / REVISE / KEEP / DEFER`처럼 이미 존재하는 기억 후보와 새 근거의 관계를 판별한다. 실제 메모리 내용의 생성은 필요할 때만 Gemma가 수행하고, raw chunk·figure ID·해시·출처·시간과 이전 버전을 보존한다. 저렴하다는 이유로 영구 삭제 결정을 남발하지 않는다.

**최소 비교:** append-only / 기존 생성 기반 갱신 / 로컬 decision+필요시 생성. 시간 순서가 있는 독립 데이터에서 원래 정확한 기억을 망가뜨리는 비율, 중요한 사실 누락, 근거 없는 추가, 최신·과거 질의 정확도, 기억 크기와 처리 시간을 측정한다. 정적 M3DocVQA만으로 이 기여를 입증할 수 없다.

**입증 조건:** 최종 QA가 비슷하더라도 장기 전이 오류와 비용의 개선을 동시에 보여야 한다. model confidence와 실제 지지 근거가 충돌하는 경우에는 저장 보류·기존 상태 유지·추가 확인으로 처리하는 설계를 검증한다. 이는 운영 배포가 아니라 연구 가설이다.

## 7. C5 — 제한된 context에 무엇을 남길지 결정

**실패 유형:** 중요한 작은 근거가 긴 검색 이력에 묻히거나, 요약·압축 중 이미지와 원문 출처 연결이 사라진다.

이미 읽은 근거 중 `KEEP / DEMOTE / RELOAD`를 판별해 원본을 보존한 채 Reader의 활성 context만 관리한다. 관련성만으로 버리지 않고 질문의 미해결 관계·상충 증거·출처를 고려한다. context를 바꾸므로 C1의 ‘동일 입력’ 속도 실험과 섞지 않는다.

**최소 비교:** 고정 최근 context / 단순 유사도 선택 / decision 선택. 같은 활성 token·이미지 예산에서 정답률·근거 회수율·reload 비용·출처 연결 오류를 비교한다. 짧아져서 빠른 효과와 더 나은 기억 선택의 효과를 분리한다.

## 8. 우선순위와 반증 기준

| 순서 | 범위 | 다음 단계로 가는 근거 | 중단·재설계 사유 |
|---|---|---|---|
| 1 | C1 구현·비용 | 올바른 멀티모달 입력, 작은 head, 비용 계측 | 인자·중복 prefill 때문에 실제 이득 없음 |
| 2 | C2 근거 충족 | 별도 근거 라벨과 독립 평가 확보 | confidence만 높고 성급한 종료 오류 증가 |
| 3 | C3 예산 탐색 | 같은 시간에서 추가 정답 회복 | 추가 호출 예산을 빼면 효과 소멸 |
| 4 | C4 장기 기억 | 시간·출처·상충을 가진 데이터 확보 | 기억 손상·누락·환각 증가 |
| 5 | C5 context 관리 | 긴 이력 조건에서 baseline보다 낫다는 근거 | 짧은 입력이나 사후 최선 선택에만 의존 |

모든 단계에서 질문 단위 paired 결과·실패 유형·전체 비용을 공개한다. 작은 PoC는 가능성 확인이며 통계적 우위·새로운 문제 해결 능력을 미리 보장하지 않는다.

## 9. 현재 contribution 문장의 안전한 형태

> 우리는 기존 멀티모달 Gemma Reader에 직접 행동 head를 붙이고 선택·인자·최종 생성 비용을 분리하는 A-RAG를 연구한다. 빠른 제어가 동일 시간 예산에서 근거 충족 검사와 대안 탐색을 더 자주 수행하게 해 답변 품질을 높일 수 있는지, 나아가 기억의 저장·검색·수정 오류를 줄일 수 있는지를 검증한다.

현재는 **연구 목적**을 설명하는 문장이다. 속도·품질·기억 신뢰성의 향상을 달성했다는 결과 문장으로 바꾸려면 각 단계 실험이 필요하다.
