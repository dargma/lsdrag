# POC: 9B head 정책의 개선 여지 빠르게 확인 (2026-10-25)

**목적:** head가 정확도와 토큰을 동시에 개선할 여지가 실제로 있는지, 그리고 오류가 어디에 있는지를 하루 안에 판정한다. 새 학습은 하지 않는다.

**Baseline (B0):** 마지막 실험의 원래 정책.
- Reader: Qwen3.5-9B@c2022362, 고정
- Head: `value_aux.pt` (sha `5191c60e…`)
- 공통 코퍼스: `musique_shared_20261023`
- Prompt: `text_rag_integrated_v5`
- 기록값 (dev64): EM 25/64, F1 49.46, 생성 158.02, 입력 16,762

**평가셋:** dev64 (기존 `evaluation_spec`의 qid 그대로).
- dev64는 이미 여러 번 사용한 집합이므로 여기서는 진단만 하고 후보를 고르지 않는다.
- reserved80은 손대지 않는다.

## 단계

| # | 내용 | 비용 | 산출 |
|---|---|---|---|
| P0 | 환경 재현: B0 dev64를 다시 돌려 기록값과 일치하는지 확인 | GPU, 실험 1회에 포함 | 재현 여부 |
| P1 | 같은 실행에서 9B 단순 baseline을 함께 측정: native, semantic_once, closed-book(final_only) | GPU, 64×4 episode | 9B baseline 표 (지금까지 없던 수치) |
| P2 | 오류 귀속 (로그 분석): 오답을 셋으로 나눈다. ① 근거 미검색 ② 검색은 됐으나 오답 ③ 8회 상한으로 강제 종료. 그리고 **두 support가 처음 관측된 step 이후에 쓴 입력 토큰**(oracle 종료 여지) | CPU | 오류 비율, 종료로 아낄 수 있는 토큰 상한 |
| P3 | Oracle-context 천장: gold support 2문단을 직접 주고 9B가 답만 생성 | GPU, 64 forward | 추론 천장 F1/EM |

## 판정 (사전 고정)

- **천장 − B0 < 10pp:** 정책 연구의 품질 여지가 작다. 토큰 절감만 목표로 삼는다.
- **②(검색 후 오답)가 오답의 다수:** 원인은 reader 쪽이다. 행동 head로는 고칠 수 없다.
- **①(미검색)이 다수:** 원인은 query 인자 쪽이다. 다음 POC는 query 후보 rerank나 규칙 기반 fallback.
- **oracle 종료 여지가 B0 입력의 30% 이상:** 다음 POC는 종료 정책. 입력 토큰을 직접 줄이는 보상이나 규칙을 쓴다.
- **semantic_once나 native가 B0와 동급 (차이 ±2문항 이내):** head의 기여를 주장하지 않는다.

## P4 (사용자 아이디어, 2026-10-25): 컨텍스트에서 지울 것을 선택하는 정책 — **보류**

> 사용자 결정: 이번 POC의 질문은 "native A-RAG 대비 selection head가 좋은가"이다. P4는 다른 질문이므로 P1/P2 판정 이후에만 검토한다. 아이디어만 보존하고 실행하지 않는다.

에이전트는 턴마다 이전 관측을 전부 다시 입력한다(문항당 약 16.7k 토큰). 정책이 관측 중 남길 것과 지울 것을 고를 수 있다면 더 가볍고 더 정확해질 수 있다.

학습 없이 먼저 천장을 측정한다. B0와 같은 head와 reader를 쓰고, 다음 턴 컨텍스트만 바꾼다.
- **oracle_keep:** 검색 결과 중 gold support가 아닌 항목을 지운다. 오프라인 gold를 쓰는 상한 측정용이다.
- **last_k:** 최근 k개 관측만 남긴다. 학습 없는 규칙이다.

2차 비교군: **native + drop 도구**. LLM이 `drop_observations(ids)`를 직접 호출하고, 런타임이 다음 턴 메시지에서 해당 관측을 제거한다. 1차 천장이 의미 있게 나올 때만 붙인다. head 방식은 같은 forward에서 슬롯별로 판정하므로 추가 생성도 추가 턴도 없다. 이 차이가 head를 쓰는 근거다.

**판정:**
- oracle_keep에서 F1이 유지 이상이고 입력이 30% 이상 줄면, train gold 기반 keep/drop head(지도학습)로 진행한다.
- last_k가 oracle_keep에 근접하면 학습이 필요 없다.
- F1이 떨어지면 지워진 관측에 연결(bridge) 단서가 있었는지 점검한다.

**한계:** n=64, seed 1개, 진단 목적. 일반화나 개선을 주장하지 않는다.
