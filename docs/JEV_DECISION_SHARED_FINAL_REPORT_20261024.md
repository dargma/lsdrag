# 공통 코퍼스 decision-head 실험 최종 보고

## 결론

선정한 다중 위치 입력 MLP head의 검증셋 개선은 최종 80문항에서 재현되지 않았다. GRPO 대비 생성 토큰은 평균 15.45% 줄었지만 F1은 5.96%p 낮았다. 목표 F1 +5%p와 생성 토큰 −30%의 동시 달성은 실패했다. 두 차이의 개별 95% 신뢰구간은 차이 없음을 포함한다. 현 결과는 성능 우위나 연구적 새로움의 증거가 아니다.

계획된 공통 코퍼스 수집·학습·검증·최종 비교는 완료했다. 원래 8시간 종료 시점인 2026-10-23 22:48 UTC 안에 완료한 작업은 아니다. 사용자의 명시적 재개 이후 단계별 상한을 둔 실행이며, 월드모델·메모리 실험은 실행하지 않았다.

## 최종 비교: 동일 80문항 × 4조건

| 정책 | F1 (0–100) | 평균 생성 토큰 | 평균 입력 토큰 | 평균 도구 호출 | 오류 episode |
|---|---:|---:|---:|---:|---:|
| 공통 코퍼스 GRPO | 27.20 | 105.76 | 4862.0 | 2.4625 | 1 |
| 선정 multi-position MLP outcome head | 21.24 | 89.42 | 4605.3 | 2.5500 | 0 |
| Native action generation | 25.88 | 104.20 | 4826.7 | 2.4875 | 0 |
| semantic search 1회 → FINAL | 18.46 | 57.62 | 2202.4 | 1.0000 | 0 |

선정 head − GRPO의 paired F1 차이는 −5.9583%p, 95% CI [−14.5833, +2.1667]%p이다. 생성 토큰 비율은 0.84553, 95% CI [0.68976, 1.01606]이다. 도구 호출은 오히려 +0.0875회다. 따라서 토큰 감소를 탐색 단계 감소로 해석할 수 없다. Native 대비도 F1 평균이 4.64%p 낮았다. GRPO의 오류 1건은 제외하지 않았다.

10,000회 문항 단위 paired bootstrap을 사용했다. 구간은 개별 지표의 marginal 95% 구간이며 다중비교 보정 또는 동시 95% 보장을 제공하지 않는다. 단일 학습 seed에 조건부인 문항 불확실성이고, 학습 seed 간 안정성을 측정하지 않는다. 통제된 지연시간 비교는 하지 않았다.

## 후보 선정과 검증 결과

| 검증64 정책 | F1 | 생성 토큰 | GRPO 대비 F1 (%p) | GRPO 대비 토큰 |
|---|---:|---:|---:|---:|
| GRPO | 22.50 | 98.41 | — | — |
| last-token outcome λ=.03 | 29.46 | 123.25 | +6.96 | +25.25% |
| last-token outcome λ=.06 | 26.08 | 112.67 | +3.58 | +14.50% |
| multi-position outcome λ=.03 | 25.18 | 76.75 | +2.68 | −22.01% |

세 후보 중 사전 고정한 `min(F1차이/.05, 생성토큰감소율/.30)`을 최대화하는 multi-position 후보를 선택했다. 최종 결과를 보고 정확도 최고였던 last-token 후보로 교체하지 않았다. 선정 기록은 최종 평가 전에 Git commit `1970df5`로 고정했다. 최종 80문항은 예약160에서 사전 SHA 순서로 선택했으며, 나머지 80문항은 이번 실험에서 사용하지 않았다.

multi-position 자체 warmstart 대비 검증 F1은 20.68→25.18, 생성 토큰은 105.28→76.75였다. 하지만 이 구조를 last-token 구조와 비교하면 입력뿐 아니라 파라미터 수, 학습 가능 범위, 초기화와 KL 기준도 달라진다. 순수한 입력 위치 효과 또는 구조 효과로 분리해 주장할 수 없다. 검증64 중 기존 노출32와 신규32의 별도 결과는 원 보고서에 보존했다.

## 학습 방식과 실제 확인한 것

- Qwen3-4B-Instruct-2507 비사고 모델을 고정하고 작은 head만 학습했다. head가 행동을 고르고 동일 LLM이 검색 인자와 최종 답변을 생성한다. 이번 비교에는 인자 재사용 최적화를 추가하지 않았다.
- train192의 native trajectory에서 공통 BC를 새로 학습했다. GRPO는 동일 초기화에서 192×4×2=1,536 episode와 660 optimizer update를 사용했다. critic은 사용하지 않았다.
- 같은 BC의 train192에서 첫/마지막 제어 가능한 상태에 대해 모든 합법 행동을 각각 두 번 실행했다. 377개 상태·2,824 episode를 확보했다. 오류15건과 강제 FINAL11건을 보존했다. 164개 상태에 행동별 평균 F1 차이가 있었지만, 이는 학습 신호의 존재이지 일반화 증거는 아니다.
- 각 행동의 후속 F1과 비용 평균으로 Q를 구성하고, 정책 확률로 가중한 기대효용을 최대화했다. KL과 entropy 항을 포함했다. 확률은 실제 학습 목적식에 사용되지만 정답 확률 또는 보정된 성공 확률은 아니다.
- 원래 구조 후보 두 개는 action·skip 계층만 변경됐으며 다른 가중치는 BC와 정확히 같았다. 구조 후보의 정규화는 학습 teacher 자료로만 계산됐다. 모든 후보 checkpoint의 유한값·해시를 직접 확인했다.
- 구조 후보는 같은 Q cache를 재사용했다. Q의 후속 정책이 원래 BC이므로 구조 후보의 자체 warmstart와는 다르며, off-policy 근사라는 한계가 있다. 행동당 두 번의 후속 표본도 제한적이다. 두 학습 방법의 수집 계산량은 일치하지 않는다.

목적식과 GRPO 식, 비용 정의는 [방법 문서](JEV_SHARED_POLICY_METHODS_20261023.md)에 있다. 비용은 도구 호출 수 + 생성 토큰/100 + 입력 토큰/10000의 대리량으로, 실제 시간이나 순수 생성 토큰 목적함수와 같지 않다.

## 데이터와 비용

문항별 20문단 환경의 shortcut 우려에 따라 공개 MuSiQue train/dev의 제목·본문을 중복 제거한 101,962문단 공통 코퍼스로 재시작했다. 모든 문항은 같은 코퍼스와 인덱스에서 검색한다. gold answer/support/decomposition은 검색 런타임 입력에 포함하지 않았다. 공개 평가 문서의 코퍼스 포함과 평가 질문·정답을 학습에 쓰는 것은 구분했다.

학습192/검증64/예약평가160은 가족 단위 분리를 검사했다. 이번 질문들의 원천은 모두 공식 train이며, 이 평가는 자체 분리 heldout이다. 전체 Wikipedia 검색이나 공식 MuSiQue 전체 벤치마크 성적으로 주장하지 않는다.

| 범위 | episode | 생성 토큰 | 입력 토큰 |
|---|---:|---:|---:|
| 과거 GRPO96 reference | 1,392 | 83,182 | 5,557,999 |
| 문항별 작은 pool 탐색 | 7,474 | 313,568 | 22,425,629 |
| 공통 코퍼스 재시작 전체 | 5,448 | 451,668 | 22,802,955 |

완료 run의 원 episode 합과 상태 집계를 대조했다. 임베딩·CPU cache fitting과 목록 밖의 과거 PPO/준비 실행은 위 LLM 토큰 합에 포함하지 않는다. 과거 작은 pool의 결과를 새 환경 결과와 합쳐 성능 주장에 사용하지 않았다.

## 해석과 다음 연구 판단

현재 확보한 것은 작은 head가 행동 확률을 출력하고, 행동별 미래 결과로 학습되며, 동일 생성 모델과 함께 실행되는 검증된 구현이다. 검증셋의 동시 개선이 최종셋에서 뒤집혔으므로 안정적인 효율 정책을 확보했다고 볼 수 없다. 작은 검증셋 선택 편향, 두 개 suffix 표본의 변동, 구조 후보의 off-policy Q 근사, 비용 대리량과 목표 토큰의 불일치는 가능한 설명이며 원인이 실험으로 확정된 것은 아니다.

후속 연구를 한다면 이번 최종80을 새 validation으로 재활용하지 않고, train-only에서 비용 목적과 행동별 표본의 안정성을 먼저 개선하는 편이 타당하다. 구조·RL 알고리즘·데이터를 동시에 더 늘리는 새 실험은 이번 보고서에서 실행하지 않았다. 예비80도 보존했다. 새로운 기여나 목표 달성을 주장하기 전에 독립 데이터와 학습 seed 반복이 필요하다.
