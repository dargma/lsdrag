# Codex 계획 요약 (쉬운 설명)

작성: Claude, 2026-11-10. 기준: `codex/PLAN.md` 개정 2. 상세는 그 문서가 우선함.

한 줄: **청크 고르는 일을 LLM의 글쓰기에서 떼어내 작은 head에게 맡기면, A-RAG가 더 적게 쓰고 더 정확해지는가**를 확인하는 실험.

## 무엇을 바꾸는가

A-RAG는 매 턴마다 도구를 하나 고름: 키워드 검색, 의미 검색, 청크 읽기, 최종 답.

- **지금**: 청크를 읽을 때 LLM이 청크 ID를 글자로 한 토큰씩 써냄. 생성 토큰의 약 28%가 여기에 쓰임.
- **바꾼 뒤**: 작은 head가 후보 청크마다 점수를 매겨 고르고, 코드가 그 번호를 실제 ID로 바꿔 실행함. ID를 쓰는 토큰이 0이 됨.
- **그대로 두는 것**: 검색어와 최종 답은 LLM이 계속 글로 씀.

## 어떻게 학습하는가 (3단계)

1. **head 가르치기**: 원래 A-RAG를 학습용 576문항에 돌려 정답지를 만들고, LLM은 고정한 채 head만 학습함.
   - 도구 선택 정답: LLM이 고른 도구.
   - 청크 선택 정답: 후보에 "정답 근거 문단"이 있으면 그것, 없으면 LLM이 고른 청크.
2. **head 붙인 모델을 강화학습**: LLM 전체와 head 전체를 풀어 놓고, 문항마다 8번씩 풀게 한 뒤 잘한 시도 쪽으로 학습함 (GRPO, 192문항 × 2회 반복).
3. **대조군**: head 없이 원래 A-RAG를 똑같은 조건으로 강화학습함. 2번과 3번의 차이가 head의 효과임.

## 보상

- 정답이면 큰 점수, 오답이면 작은 점수.
- 정답일 때만 "도구를 덜 부를수록", "토큰을 덜 쓸수록" 조금 더 줌.
- 오답은 아무리 짧아도 정답보다 높을 수 없게 설계됨.

## 무엇을 비교하는가

개발용 192문항에서 5가지를 비교함.

| 조건 | 설명 |
|---|---|
| N0 | 원래 A-RAG, 학습 전 |
| H0-G | 도구 head만 붙임 (청크 ID는 LLM이 씀) |
| H0-P | 도구 head + 청크 head, 강화학습 전 |
| H-RL | H0-P를 강화학습한 것 (주인공) |
| N-RL | 원래 A-RAG를 강화학습한 것 (대조군) |

성공 기준: H-RL이 N-RL보다 정확도가 같거나 높으면서 도구 호출이 10% 줄고 생성 토큰도 주는 것.

## 진행 순서와 멈춤 지점

| 단계 | 하는 일 | 멈추는 조건 |
|---|---|---|
| S0 | 환경 설치, 원래 A-RAG 수치 재현 | 예전 수치(F1 약 19.3)와 안 맞으면 원인 규명 전까지 정지 |
| S1 | 정답지 수집, head 학습 | head의 청크 선택이 LLM보다 못하면 정지 |
| S2 | head 붙인 모델 평가 | – |
| S3 | 보상이 제대로 신호를 주는지 소규모 사전 점검 | 신호가 약하거나 8번 시도가 다 똑같으면 정지. 호출 절감 신호가 드물면 사용자에게 확인 |
| S4 | 강화학습 2개 (각 3~5시간) | 짧은 smoke에서 수치 오류가 나면 정지 |
| S5 | 최종 평가와 보고서 | – |

## Claude가 보는 약한 고리

- **생성 토큰 감소**: 구조상 거의 확실함.
- **정확도 향상**: 1단계에서 근거 문단을 정답지로 쓴 덕에 기대할 만함.
