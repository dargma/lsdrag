# Claude ↔ Codex 소통 프로토콜

작성: Claude, 2026-11-10. 대상: Codex(GPT). 제안이므로 고칠 점은 `codex/`에 적어 주면 맞추겠음.

## 1. 폴더 소유

| 폴더 | 쓰는 쪽 | 읽는 쪽 |
|---|---|---|
| `codex/` | Codex만 | Claude |
| `claude/` | Claude만 | Codex |
| 그 외 (`src/`, `scripts/`, `configs/` 등) | Codex (실험 계획·진행 담당) | Claude는 읽기만. 사용자가 시키면 그때 수정 |

상대 폴더의 파일은 고치지 않음. 고칠 점은 자기 폴더에 의견으로 남김.

## 2. Claude가 저장하는 파일

| 파일 | 내용 |
|---|---|
| `claude/README.md` | 시작점. 사용자가 밝힌 목표, PoC 원칙, 이전 실험의 장애물, 파일 목록 |
| `claude/PROTOCOL.md` | 이 문서 |
| `claude/REVIEW_NN_<대상>.md` | 검토 의견. 검토 1회당 파일 1개, 번호는 01부터. 한번 쓴 검토 파일은 고치지 않음 |
| `claude/RESEARCH_BRIEF_*.md` | 사용자가 준 자료 원문 |

## 3. 검토 의견 형식

검토 파일 맨 위에 대상을 고정함: 파일 경로, 커밋 해시(미커밋이면 sha256 앞 12자리), 읽은 시각(UTC).

의견은 항목마다 번호와 등급을 붙임.

| 등급 | 뜻 | Codex에게 기대하는 것 |
|---|---|---|
| **BLOCK** | 이대로 실행하면 결과를 해석할 수 없거나 목표를 측정하지 못함 | 실행 전에 반영 또는 반박 |
| **FIX** | 고치는 편이 분명히 나음 | 반영 또는 이유를 적고 거절 |
| **ASK** | 계획만으로는 판단할 수 없음 | 답변 |
| **NOTE** | 참고 | 응답 불필요 |

각 항목은 세 줄로 씀: 무엇이 문제인지 / 근거(파일:줄, 이전 실험 수치, 로그) / 제안하는 수정. 근거 없는 의견은 쓰지 않고, 확인하지 못한 것은 "미확인"이라고 표시함.

예: `R01-3 [FIX] 보상의 호출 감점이 그룹 표준화 뒤에 사라짐 / 근거: ... / 제안: ...`

## 4. Codex에게 요청하는 응답 방식

- `codex/RESPONSE_NN.md`(검토 번호와 같은 NN)에 항목 ID별로 **반영 / 거절 / 보류** 중 하나와 한 줄 이유를 적어 주기 바람.
- 반영했으면 바뀐 파일과 위치를 같이 적어 주기 바람.
- BLOCK 항목에 동의하지 않으면 실행 전에 거절 이유를 남겨 주기 바람. Claude가 재반박하거나 철회함. 두 번 오가도 안 풀리면 사용자에게 올림.

## 5. Claude가 언제 읽는가

- Claude는 사용자가 말을 걸 때만 움직임. `codex/`를 계속 지켜보지는 못함.
- 그래서 검토가 필요한 시점에 사용자가 Claude에게 알려 줘야 함. 검토 받을 파일은 `codex/README.md` 맨 위에 "검토 요청: <파일>" 한 줄로 표시해 주면 그것부터 읽음.

## 6. 검토 기준 (사용자 지시)

1. 목표에 맞는가: selection head로 A-RAG의 iteration↓ → 생성량↓ → 정확도↑.
2. head KD → GRPO 설계가 그 효과를 실제로 만들어 내고, 측정으로 확인되는가.
3. `claude/README.md`에 적은 이전 실험의 장애물을 피하는가.
4. PoC답게 중복·장황함이 없는가.
5. 각 단계 앞에 smoke가 있고, 무엇을 확인하며 통과 기준이 무엇인지 적혀 있는가.

## 7. Git

- 브랜치 `jev_v2.2`, 작업 폴더 `/content/local_fast/lsdrag-code-v2.2` 공유.
- Claude는 `claude/` 경로만 커밋함 (`git add claude/`). 사용자가 요청할 때만 커밋·push함.
- push 전에 `git pull --rebase`로 상대 커밋을 먼저 받음. 서로 다른 폴더만 건드리므로 충돌은 없어야 함.
- 브랜치 전환, `reset`, `stash`, force push는 하지 않음.

## 8. 실행 자원

- Claude는 GPU 작업을 띄우지 않음. 필요하면 사용자에게 먼저 물음.
- Claude는 Codex의 프로세스와 결과물을 건드리지 않음.
