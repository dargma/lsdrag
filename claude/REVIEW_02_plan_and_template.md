## 총평

구조(2절), 대조군 정의(6절), replay로 LLM까지 기울기를 보내는 변경(5절)은 맞고 그대로 가면 됨. 순차 선택 + STOP도 동의함.
문제는 **학습 신호**임. 1차는 LLM을 흉내만 내고, 2차는 궤적 단위 보상 하나만 씀. 이것은 v2.1에서 4개 arm이 호출을 못 줄인 조건과 같음. 구조만 바뀌고 실패 원인은 그대로 남음.

## 의견

**R02-1 [BLOCK] 1차 KD가 LLM 자신의 선택을 따라 하므로 정확도가 오를 수 없음**
- 문제: teacher가 같은 base LLM의 native 경로임. head가 완벽히 배워도 H0-P의 선택은 N0와 같아지고, 못 배운 만큼 나빠짐. 정확도 향상은 전부 2차 GRPO에 맡겨짐.
- 근거: PLAN 4절 "teacher는 같은 base LLM의 native constrained 경로", "support labels는 KD 정답으로 섞지 않음". N0 수준은 F1 19.3, 빈 답 41%, 3·4hop 근거 전부 확보 0~3% (`RESULTS.md` 5절).
- 제안: train 문항의 근거 표시로 chunk 라벨("후보 중 안 읽은 근거")과 FINAL 라벨("근거 전부 읽음")을 만듦. 평가 문항에는 쓰지 않으므로 누출 아님. `claude/PLAN.md` S1 표 참고. LLM 선택 일치율은 보조 지표로만 보고.
- 사용자 결정 사항임 (`claude/PLAN.md` D2). 사용자는 "라벨 생성 → head KD"라고만 했고 라벨 출처는 정하지 않았음.

**R02-2 [BLOCK] 2차 보상이 v2.1의 신호 문제를 그대로 가짐**
- 문제: 궤적 단위 보상 하나뿐이라, 8개가 모두 오답인 그룹의 결정은 신호 0임. 단계별 보상은 "범위 제외"로 뺐음.
- 근거: v2.1에서 결정의 51%가 신호 0, 단계별 근거 보상은 오프라인에서 11% (`HANDOVER.md` 2절). PLAN 1절 "별도 value/process reward는 제외", 7절 "신호가 없을 수 있음… 해결 보장은 아님".
- 제안: 이미 구현된 `evidence_step_rewards`(`src/lsdrag/fullft.py:197`)를 두 arm에 같은 규칙으로 적용. 결정 i에 속한 것(head logp 또는 그 단계 토큰)에 같은 A_i를 씀. head arm 전용이 아니므로 대조가 깨지지 않음.

**R02-3 [FIX] 효율 항이 너무 작아 호출·토큰이 안 움직일 것으로 예상됨**
- 문제: 정답일 때 호출 1회 차이 = 0.15/8 = 0.019, 토큰 100 → 140 차이 = 0.008. 정답/오답 차이는 0.8. std로 나누지 않으므로 효율 기울기는 정확도 기울기의 약 1/40임. 호출 감점은 EM=1인 궤적에만 걸리는데 그 비율이 낮음.
- 근거: PLAN 7절 식에 직접 대입. v2.1은 곱셈형 `0.8^호출`(호출 1회 = 보상 −20%)로도 호출을 못 줄였음.
- 제안: 실행 전 오프라인 검증에 통과 기준을 둠. 예: "정답 궤적이 2개 이상인 그룹에서 호출 수와 advantage의 상관 ≤ −0.3". 못 넘으면 계수를 키우거나 곱셈형으로.

**R02-4 [FIX] 근거가 부족한 상태라는 사실이 계획에 없음**
- 문제: 목표를 "호출 10% 감소"로 두었는데, 현재 모델은 과다 호출이 아니라 과소 수집임. 호출을 줄이라는 신호는 정확도와 충돌함.
- 근거: 2~4hop에 평균 2.4회 호출, 근거 전부 확보 0~3% (`RESULTS.md` 5절 "호출이 줄지 않은 이유" 4번).
- 제안: 학습 전에 N0 궤적에서 낭비 호출 비율(근거 아닌 청크 읽기, 같은 검색 반복)을 먼저 잼. 10% 미만이면 목표를 "정답당 호출 수"로 바꿈. `claude/PLAN.md` S0.

**R02-5 [FIX] KD 표본이 작음**
- 문제: 192문항 중 144문항으로 학습. read 상태는 에피소드당 1개 안팎이라 pointer 학습 예가 수백 개 수준. 입력은 2560차원임.
- 근거: PLAN 4절 수집 제안. 평균 호출 2.4회.
- 제안: train576 전체에서 수집 (문항당 greedy 1 + 샘플 2). GRPO도 같은 train pool에서 뽑으므로 누출 문제 없음.

**R02-6 [FIX] 통과 기준이 숫자로 없음**

- 근거: PLAN 4절 끝, 5절 끝, 7절 끝, 8절.
- 제안: 단계마다 수치 기준을 지금 적음. 예: replay logp 차이 < 0.05, 행동 순서가 다른 그룹 ≥ 50%, 신호 0인 결정 < 20%, 판정 iteration = 2.
